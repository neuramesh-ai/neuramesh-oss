# Status snapshot — 2026-07-07 (v0.20.2)

> Point-in-time gap analysis: goals ([04-build-plan.md](04-build-plan.md), [05-engineering-philosophy.md](05-engineering-philosophy.md)) vs. what has shipped vs. what's pending. The build plan's own status sections run through v0.12.1 (2026-07-02); this snapshot carries the picture forward through v0.20.2. It does not replace [decisions.md](decisions.md) (the log) or docs/04 (the plan) — it's the "where are we" answer, written down.

## Where we stand

The 6-week alpha plan shipped in full, and the frontier has moved well past it: 20 minor versions in ~3 weeks, currently **v0.20.2**. The core promise is live end to end — an enforced loop (backlog → triage → design gate → plan gate → build → PR review with CI → human accept → squash merge), multi-runtime agents (Claude / Codex / agy), memory + lessons + skills (including the bundled design-craft pack), benchmark-measured model packs with a public benchmarks page, a signed auto-updating desktop app with continuous backend deploys, Stripe billing rails in code, and an iOS companion **submitted to the App Store 2026-07-07** (demo account created and used in the submission; TestFlight v0.1.3 live).

What's pending falls into four buckets, in rough priority order.

## 3. Goals-level gaps (the strategic ones)

- **External teams.** The alpha success criterion was "2–3 teams running the full loop daily." Everything so far is user-zero-proven, not team-proven. The plan names the prerequisites: the clean-machine dogfood above, and **KMS/pgsodium before external teams** touch it. This is the biggest gap between goals and achievement.
- **Budgets as evidence.** "Agent overhead vs raw Claude Code <10%" is a release gate with partial measurements (plan latency, cold-start floor) but no green scorecard; chat latency is a known miss until the warm pool lands.
- **Billing live-ness.** The Stripe code is real and correctly gated ([billing.ts](../packages/control-api/src/billing.ts): webhook is the only writer of `workspaces.plan`), but whether prod env vars/price/webhook are configured and a checkout has been exercised end to end isn't verifiable from the repo — confirm before anyone hits a paywall.
