# NeuraMesh source release: Free is the local desktop app, Pro is the cloud

> **Status: proposal, revised 2026-09-12 after the Superset review. Nothing here is built.** Founder
> direction: publish the source the way Superset did. The desktop app is free forever, with no account,
> no cloud, and no limits, on your own machine with your own subscriptions and keys. Pro is the hosted
> cloud: invites, cloud machines, sync across devices, the mobile app, and everything else the cloud
> provides. No trial. Clerk appears only when a user upgrades to Pro. This release runs Mon 2026-09-14
> to Sun 2026-09-27. **Founder time cap: 22 hours.** Agent time is not capped. If the cap is hit, the
> repo goes public as a snapshot with the gaps named in the README (the cap rule). Nothing in this
> round touches a production pipeline before Sep 28.
>
> **Reviewed 2026-09-12:** [review.md](review.md) is the adversarial review (four findings change the build:
> the Local identity, the size of D9, the container prerequisite, and the missing export). The build follows
> [implementation-plan.md](implementation-plan.md), which applies the amendments as plan-first units on a
> calendar. The visual contract is the canvas beside this file (`node build.mjs`, open `index.html`).

## 0. The one-paragraph version

Two plans, never confused. **Free** is the desktop app in Local mode: the app starts a small local
stack on your machine (Postgres, PowerSync, control-api), creates a local identity with no sign-up, and
runs your agents on your own subscriptions. No limits on projects, agents, or tasks. Nothing leaves the
machine. **Pro** is $22 per seat per month, paid at upgrade, no trial: the hosted cloud with your team,
cloud machines and credits, sync across devices, the browser app, the mobile app, connectors, and
routines that run while your laptop is closed. The upgrade button creates the account (Clerk) and the
subscription (Stripe) in one flow. Then the same desktop app gains a Cloud connection beside Local. Cloud
workspaces and their threads sync to the cloud and show under a Cloud section in the left nav. Local
workspaces and threads stay local and stay in the same view. Both run at once. The source is public
under the Elastic License 2.0. After Sep 27 the maintainers ship security fixes only, through 2026-12-18.

## 2. What Superset does (reviewed 2026-09-12)

- License: Elastic License 2.0 in `LICENSE.md`. GitHub shows "Other" because the file is Markdown with a heading, so we name ours `LICENSE` with the canonical text.
- The whole monorepo is public: api, web, admin, relay, realtime, mobile, marketing, docs. Nothing is held back except the hosted service itself.
- Free: "The desktop app is free forever. Running agents in parallel on your own machine will never require payment. Anything we charge for will be an optional service on top." Their free tier still requires a hosted account. Ours does not, by founder direction.
- Pro at $15 to $20 per user per month: remote access, automations, Linear and Slack, unlimited users, mobile. No trial.
- Self-host is not on the pricing page. The README grants it under the license and points at the developer setup (Docker Postgres plus Electric, a seeded dev account, a "Sign in as dev" button). That is the same shape as our Local mode, minus the account.
- Community files: `CONTRIBUTING.md` (PRs welcome, issue first for features), `SECURITY.md` (GitHub private vulnerability reporting, email fallback), `CODE_OF_CONDUCT.md`, `DEVELOPMENT.md`.
- Auth: better-auth, self-contained. Ours is Clerk. Under this plan Clerk is a Pro-only dependency, so the difference stops mattering for Free.

Each is a line in `docs/decisions.md` when answered. D1, D2, D4 are unchanged from the first draft.

- **D1 License.** Recommendation: **Elastic License 2.0**, file named `LICENSE`. It does not allow a third party to offer the software as a hosted service. AGPL-3.0 does not reserve hosting. MIT and Apache-2.0 let anyone host our cloud. The `NOTICE` MIT packs stay MIT.
- **D2 Repo.** Recommendation: **a fresh snapshot in a new public repo, with the private repo kept as the deploy source until after the flowe test.** A sync workflow mirrors public `main` into the private repo. Vercel, WIF, and every secret stay where they are. The pipeline move is an optional slice after Sep 28. Name: `neuramesh-ai/neuramesh-oss` (created by George, 2026-09-12). **The releases repo never moves.**
- **D3 Plans (revised).** **Free** is the desktop app in Local mode: free forever, no account, no cloud, no limits. **Pro** is the hosted cloud at $22 per seat per month, paid at upgrade, no trial. The plan id `cloud` keeps its name in code and Stripe. The label changes from Team to Pro on every surface. There is no hosted free plan: a hosted sign-up goes straight to Pro checkout, and a hosted workspace on the `free` plan is a paywalled shell (read your data, upgrade, or export). Existing hosted sign-ups become paywalled shells with no new grants and no new machines. This reverses the Sept 7 landing decision: the free path is download-first again, and the browser app is Pro.
- **D4 Benchmark suite.** Recommendation: **exclude `packages/bench/suite/**`** (move to a private repo).
- **D5 Mobile.** Recommendation: **include the source, gate the app to Pro.** The companion needs the cloud. EAS holds the signing credentials.
- **D6 Credits.** No free grants of any kind. Pro activation grants `CLOUD_SEAT_MONTHLY_CREDITS` times seats once, then the monthly refill continues for `cloud` only.
- **D7 Local mode architecture (new).** Recommendation: **L1, an app-managed Docker stack.** The desktop app ships a compose file and starts it (`docker compose up -d`). It waits for health and seeds the local identity. Docker Desktop is the one prerequisite. When Docker is absent or not running, the app says so with an install link and a retry. Every piece exists today, so it fits the window. **L2, bundled binaries with no Docker** (embedded Postgres binaries, the PowerSync service and control-api as child processes) is the v2 target after the flowe test. **L3, an in-process store** (PGlite or the `MemoryStore` in `packages/control-api/src/store/memory.ts`) is rejected for v1: PowerSync needs Postgres logical replication, and the renderer reads only from the PowerSync SQLite.
- **D8 Auth for Pro (new).** Recommendation: **keep Clerk, and set it up only at upgrade.** Free has no account at all, so Clerk is never in the free path. Switch to better-auth later only if Clerk costs bite or self-hosting for teams ever matters. This round does not add an auth provider.
- **D9 Local and Cloud in one view (new).** The desktop holds a Local connection always and a Cloud connection after upgrade, both open at once. The left nav shows a Cloud section with the cloud workspaces and their threads under it, beside the local ones, the way Superset does. Cloud workspaces and threads sync to the cloud. Local workspaces and threads stay on the machine. The user opens, starts, and manages local and cloud threads from the same interface, with local subscriptions on local threads and the cloud plan on cloud threads. No relaunch. The user's Mac joins a cloud workspace as a machine, which the cloud already supports. A local workspace moves into a Pro workspace on Pro, within the plan's limits (D16, 2026-09-12, [implementation-plan.md](implementation-plan.md) U7).

## 5. Design

### 5.1 Local mode (Free)

- **Stack.** `apps/desktop/resources/local/docker-compose.yaml`: `pgvector/pgvector:pg16` with `wal_level=logical`, `journeyapps/powersync-service` pinned, and `ghcr.io/<org>/neuramesh-control-api:<version>` built by a new `control-api-image.yml` in the public repo (GHCR is free for public repos). The image runs `node scripts/migrate.mjs` then `tsx src/server.ts`. `migrate.mjs` applies `supabase/validate/auth-shim.sql` when the `auth` schema is absent and adopts from `0001`. The image boot step also creates the `powersync_storage` role and database (`dev/stack/init/98-storage.sql`) and the publication (`99-publication.sql`), because `00-bootstrap.sh:27` skips publication migrations and PowerSync cannot start without them. Inside the container control-api binds `0.0.0.0`. The compose file publishes `127.0.0.1:8788:8787` and `127.0.0.1:58081:8080`, so nothing is reachable from the network (the dev compose already does this at lines 16 and 44). The image is published to GHCR from the private repo first, with package visibility public, so S2's smoke test can pull it before the public repo exists. Env: `DATABASE_URL`, `PORT=8787`, `NM_LOCAL=1`, `NM_SYNC_KEY`, `NM_ADMIN_TOKEN`, `FLEET_AUTOPROVISION=off`, `PUSH_ENABLED=0`, `NM_EMBED=on` optional. Unset on purpose: `CLERK_*`, `STRIPE_*`, `RESEND_API_KEY`, `POSTHOG_KEY`, `NM_CONNECTOR_KEY`, `STARTER_GOOGLE_API_KEY`, `FLEET_SECRET`, `CRON_SECRET`. Each absent key already degrades to a no-op or a clean 501 or 503 (`mail.ts:62`, `billing.ts:19`, `analytics.ts:12-18`, `app.ts:367-378`, `credits.ts:116-117`, `fleet.ts:155,199-201`).
- **`NM_LOCAL=1`** on control-api. `workspacePlan()` returns full entitlements: no seat cap, no project cap, no machine cap, schedules allowed. The actor header and dev tokens are accepted. The starter brain answers an honest "bring your own key" 503. `GET /.well-known/nm-config` returns `{ mode: 'local', powersyncUrl, authMode: 'local', localUserId, workspaceId }`, so the desktop no longer hard-codes `DEV_USER`. Without `NM_LOCAL`, `NM_ALLOW_ACTOR_HEADER` will default to closed (today `app.ts:518` is open unless it is `'0'`). The `test` scripts in `packages/control-api/package.json`, `ci.yml:96`, `scripts/dev-app.sh`, `dev-e2e.sh`, and `verify-shared-compute.sh` set it to `1` explicitly.
- **Local identity.** On first run the app generates `NM_SYNC_KEY` and `NM_ADMIN_TOKEN` into `~/.neuramesh/local/.env` and passes them to compose with `--env-file`. control-api seeds one local user and one workspace on boot (`NM_LOCAL=1`, idempotent, through `resolveClerkUser` at `pgstore.ts:797` with a fixed local subject and `createWorkspace` at `pgstore.ts:295`). The desktop fetches its sync token from `/auth/dev/token` (`sync.ts:272`) instead of signing with the committed key, because the per-install key rejects `token.ts:5`. `powersync.yaml` reads the key, the admin token, the JWKS URL, and the audience from env. There is no sign-in screen in Local mode. The Local connection then resolves the seeded workspace through the same path as the clerk branch (`sync.ts:826-843`), so `needsOnboarding` derives from agents and the onboarding wizard runs: it hires the first agents and collects the user's keys. Without this step the seeded workspace has no agents and no agent ever replies.
- **Orchestration in the app.** A new `apps/desktop/src/main/localStack.ts`. It finds `docker` with the same PATH resolution the agent runtimes use (`runtime/cli.ts:53`), because a Finder launch has a minimal PATH. It tells three failures apart: Docker not installed, Docker installed but not running, and the daemon socket refused. It copies the compose file to `~/.neuramesh/local/` and runs `docker compose up -d`. First run pulls three images and applies 141 migrations, so the UI shows "Downloading" with no clock until the images exist. The 90 second health budget starts after that, polling `/healthz` and `/.well-known/nm-config`. UI states: "Docker not found" (install link, retry), "Docker not running" (open Docker, retry), "Downloading", "Starting local stack", and "Local" (a badge in the shell). `docker compose down` on quit is off by default so restarts are instant.
- **Connections.** A new `apps/desktop/src/main/connections.ts` owns the backends and replaces the four load-time reads (`sync.ts:62,73`, `authipc.ts:27-45`, `auth-clerk.ts:61`) and `AUTH_MODE` (`apiauth.ts:36`). A connection is an API URL, a PowerSync URL, an auth mode, an identity, a replica path, and its own `PowerSyncDatabase`. Three kinds: `local` (from `localStack`, always present), `cloud` (the baked URLs, present after upgrade), and `custom` (a Settings "Server" field for people who run the compose file on a server). Both Local and Cloud stay open at once. The `sync.ts` singletons (`WS`, `API_URL`, `db`) become fields on a `Connection`, and every IPC handler routes by the workspace id in its payload to that workspace's connection. The agent host starts once per connection (`startAgentHost` already takes `db`, `apiUrl`, and `workspace`). Notifications come from both. The renderer's `navtree.ts` builds a Local section and a Cloud section, each with its workspaces and their threads, in the same left nav. Opening a cloud thread reads and writes through the Cloud connection, and a local thread through Local, with no relaunch. `switchWorkspace` (`sync.ts:353-362`) stays only for switching between two workspaces on the same connection. Precedence for URLs: env in dev, then the workspace's connection, then the baked defaults. The browser build drops its PowerSync literal fallback (`renderer/web/main.tsx:30-32`).
- **What Free has.** Every room kind. Every agent runtime on your own keys (Claude Code, Codex, `agy`). Tasks, threads, memory, whiteboards, files, and skills. Routines that fire from the daemon while the app is open. Drafted posts and articles, published by hand, because connectors need our OAuth apps. No limits.
- **What Free does not have.** Cloud machines, invites and seats, sync across devices, the browser app, the mobile app, connectors that publish, the relay and browser terminal, routines while the laptop is closed, email. Each is a Pro line on the upgrade sheet, not a nag. After upgrade, every one of them runs from the same desktop app, under the Cloud section of the left nav, beside the local threads.

### 5.2 Pro (the hosted cloud)

- **Rename.** `PLAN_LABELS` in `entitlements.ts:34` becomes `{ free: 'Free', cloud: 'Pro' }`. Every surface that says Team or Individual changes: pricing, upgrade modal, refusals, email templates, `docs/07`.
- **No hosted free plan.** The gate has two parts, because the API has no single chokepoint. Part one: a `/v1/*` middleware keyed on the body's workspace refuses a `free` hosted workspace, plus the same check inside `executeCommand`. Part two: a written exemption list, tested: `GET` reads, `/auth/*`, `/v1/billing/*`, `workspace.create`, `machine.register`, `machine.heartbeat`, and the sync token. `NM_LOCAL=1` bypasses the gate. The refusal shape matters: the PowerSync upload lane (`/v1/messages`, `/v1/artifacts`, whiteboards) answers `409` with `code: PLAN_LIMIT`, because the uploader drops a 409 and retries anything else forever while holding downloads (`sync/upload.ts:63-67`). `/v1/commands` answers `402 PLAN_LIMIT`, which the desktop already routes to the upgrade modal. The modal itself comes from the plan read at boot (the workspace row is synced), not from a failed write, so a shipped client that predates S1 still shows the door instead of a wedge. Existing sign-ups keep their data readable (sync and `GET` reads stay open) and see the upgrade modal on the next action.
- **Hosted onboarding.** Today the web sign-up creates no workspace (`onauth.ts:1-40` claims invites and sends mail) and the onboarding wizard creates it later (`webnm-onboard.ts`, `sync.ts:1143`), but checkout needs a workspace id (`app.ts:895-896`). So the first hosted sign-in creates the workspace server-side (`workspace.create` is exempt from the gate), then lands on Pro checkout at once (`POST /v1/billing/checkout`, `billing.ts:26-40`, no `trial_period_days`). The wizard runs after the webhook flips the plan. The Stripe webhook does four things it does not do today: read the previous plan with `workspacePlan()` before `setWorkspacePlan` (`app.ts:336`), resolve `ownerUserId` from `workspace_members` where `role = 'owner'`, mint the runner only when no live `kind = 'runner'` row exists, and grant `CLOUD_SEAT_MONTHLY_CREDITS * seats` once with `grantCredits(..., 'promo', subscriptionId)` so a redelivered event grants nothing. No runner at workspace create (`handler/workspace.ts:68-82`). Refill worklist filters to `cloud` (`credit-ledger.ts:203-213`). `credits.ts:215` and `rates.ts:108` gain a free branch. Enable `invoice.payment_failed` (`docs/07:39`).
- **Upgrade from the app.** "Upgrade to Pro" in Local mode reuses the desktop OAuth handoff shape, not a custom URL scheme (none is registered, and `billing-return.tsx:51-55` records the failed attempt). The app calls `POST /auth/desktop/start`, opens `neuramesh.app/pro?nonce=` in the browser, and polls `/auth/desktop/poll` with the window raised from 60 seconds (`auth-clerk.ts:74`) to 15 minutes, because sign-up plus checkout takes longer than a sign-in. The page runs sign-up, workspace creation, and checkout, then completes `/auth/desktop/complete`. The app adds the Cloud connection, and the new cloud workspace appears under Cloud in the left nav, beside the local workspaces. The user starts a cloud thread from the same view while local threads keep running (D9).
- **Our own routines** run on one runner in our own workspace, which is already `cloud` (`docs/design/cloud-first-2026-08/rollout.md:255`). Before S1 deploys, confirm that plan and that runner's balance. That runner is the only NeuraMesh compute we pay for after Sep 27.

### 5.4 Cutover, in two parts

**S6a (in this round, by Sep 27, no production risk).** Create the public repo. Push the scrubbed tree as one initial commit (`git checkout --orphan`). Add `sync-from-public.yml` to the private repo: on a schedule and on `repository_dispatch`, fetch public `main` and update private `main` (one forced update at cutover, then fast-forward only). Tag the old private `main` as `main-archive-2026-09` first. Vercel, WIF, and every secret stay bound to the private repo. Re-create the local worktrees on the new history. The public repo carries `ci.yml`, `local-stack-smoke.yml`, `control-api-image.yml`, and `public-scan`. Pre-publish gate: the cloud PowerSync instance's `client_auth` lists no `nm-dev` key. The committed HS256 key goes public with the source, and if the cloud still accepted it, anyone could forge a `sub` and read any workspace.
