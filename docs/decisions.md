## 2026-07-28 — RLS closed on the 15 tables prod left open; the guard is a CI test, not a habit

Supabase's security advisor mailed 16 critical findings against **production** (the production project, not the dev one): 15 × `rls_disabled_in_public` + 1 × `sensitive_columns_exposed`. A scan of all 100 migrations reproduced the count exactly — **37 tables declared, 23 with RLS, 14 without**, plus the runner's own `schema_migrations`. No migration has ever issued a REVOKE, so Supabase's default `grant all on tables to anon, authenticated` stood on every one; PostgREST is live on the project (unauthenticated probe returns `401`, not a connection failure). **RLS off + those grants + a live REST endpoint = anyone holding the anon key (public by design) could SELECT/UPDATE/DELETE those tables.** The write side was the sharper edge: six sit in the powersync publication, so an unqualified DELETE would have replicated to every client. Worst rows exposed: `desktop_auth_sessions` (holds a **verified nm session** mid-handoff — a direct read walks around the `poll_secret_hash` gate 0046 was built to enforce), `nm_users` (clerk_user_id → email, almost certainly the `sensitive_columns_exposed` hit), `emails` (every recipient + `payload`), `connector_secrets` (ciphertext only, but writable), `device_tokens`. **Why it drifted:** RLS was never load-bearing here — clients read through PowerSync, control-api writes as the table owner and bypasses RLS — so a table without it breaks nothing and signals nothing. The last table to get RLS was `policies` (0068); **every table from 0074 onward missed it — 26 migrations of silent drift.** **The fix ([0100](../supabase/migrations/0100_rls_deny_all.sql)) is permissions-only:** RLS enabled with **no policy** = deny-all, already the posture of `provider_credentials`/`task_counters`/`workspace_invites` (which is exactly why the advisor never flagged those three). Deliberately absent: **no `force row level security`** (owner bypass is what keeps control-api working — FORCE would break every write, and a second test now pins that it stays off everywhere); **no read policies** (these are reached over PowerSync or the control-api, never PostgREST, so a `members_read` would widen the surface for no caller — logical replication reads the WAL, which RLS does not touch); no grants, so the migration names no roles and runs identically on CI postgres, the dev stack and cloud. **One trap found by running it:** `schema_migrations` is created by [migrate.mjs](../packages/control-api/scripts/migrate.mjs), not by a migration, so it is **absent** wherever the `.sql` files are applied directly by psql ([ci-db-bootstrap.sh](../scripts/ci-db-bootstrap.sh), [validate-db.sh](../scripts/validate-db.sh)) — an unguarded `alter table` there aborts the whole bootstrap under `ON_ERROR_STOP=1`. Guarded with `to_regclass`. **The real deliverable is the guard, not the migration:** [rls.pg.test.ts](../packages/control-api/test/rls.pg.test.ts) fails CI when any public table lacks RLS, so the next forgotten table costs one line in the same PR instead of an advisory email months later (enforced, not prompted — doctrine §4). It rides the job-level `DATABASE_URL` in ci.yml, so `pnpm -r test` picks it up with no workflow edit. **Evidence** (single container, [scratchpad proof](../scripts/test-pg.sh) list extended): before 0100 the guard goes **RED** listing all 14 (`expected [ 'beats', 'connector_secrets', …(12) ] to deeply equal []`); 0100 applies clean; after 0100 **`✓ rls.pg.test.ts (2 tests)` + `✓ loop.pg.test.ts (21 tests)`, 23/23**. Full workspace green: typecheck all 7 packages · unit 655 passed (web 15 · shared 323 · client-core 15 · bench 46 · control-api 256 + 82 pg-skipped) · desktop suite ok. A four-way matrix confirmed the 3 `loop.pg.test.ts` failures seen in the full 16-file pg run are a **pre-existing cross-suite race**, identical with and without 0100 and absent when that file runs alone — untouched by this change, filed separately. **Deploy notes:** migration auto-applies on the prod deploy; no Vercel env; no desktop work. **The one thing to confirm before merge — cloud PowerSync's replication role.** It is a dashboard connection string, unreadable from the repo. If it connects as `postgres` (the table owner) this is a no-op for sync; if it uses a dedicated role, RLS *would* apply to its initial-snapshot SELECTs and a re-snapshot would come back empty. Logical replication itself is unaffected either way — only the snapshot path is at risk.

## 2026-07-02 — Orchestrator sweep spam: NO_REPLY is a policy, not an equality check

Rex was posting "Board is empty; #1004 is accepted… NO_REPLY" to #dev every ~15 minutes — the plan is at most 3 channel updates a day (morning/midday/evening summaries; the 15-min tick's *monitor* half is supposed to be silent unless something needs a human). Root cause was a compounding pair: **(1)** the stand-down gate was `reply === 'NO_REPLY'` (exact equality), so a model that wrapped the sentinel in narrative slipped straight past it and the chatter posted; **(2)** `channelNeedsMonitor` counted *any* new message as channel activity — including the orchestrator's own leaked note — so each post re-armed the next tick's monitor off itself, forever. Fixes, all structural: **(a)** [replypolicy.ts](../apps/desktop/src/main/replypolicy.ts) — `isStandDown()` stands down when the sentinel is the whole reply or its own first/last non-empty line (markdown emphasis + trailing punctuation tolerated; a NO_REPLY quoted mid-alert still posts), applied to both the sweep and the channel-mention wake; **(b)** monitor re-arm now counts **human** messages + open-task movement only — agent chatter can never wake the monitor (agent work that matters rides task state, which the open-task clause still catches); **(c)** an enforced anti-repeat: a body identical to one already posted in the channel today never posts again, whatever the model decided (the prompt's "do NOT repeat a nudge" is now a guard, not a request). Summaries keep their existing 3/day gate (`SUMMARY_MARKER` + `summaryPostedToday`), so post-fix cadence = ≤3 summaries + genuinely actionable monitor notes. **Evidence:** [replypolicy.test.ts](../apps/desktop/src/main/replypolicy.test.ts) 6/6 (`tsx --test`) including the verbatim observed failure; desktop typecheck + build green. **Bug 3 — PowerSync's native lib never loads inside the asar** (commit `5df935e`, #40, v0.4.3). Once Bug 2's fix let `startSync` actually run in the packaged app, it threw `SqliteError: dlopen(.../@powersync/node/lib/libpowersync_aarch64.macos.dylib.dylib) errno=20`. `@powersync/node`'s `lib/db/SqliteWorker.js` resolves the core lib from `import.meta.url` — the **`app.asar` *virtual* path** — but SQLite's `load_extension` uses **raw `dlopen`**, which does **not** follow Electron's asar→unpacked redirect (only `process.dlopen`, used for `.node` addons, gets that patch). **The enforced release gate (the real lesson):** `pnpm -r typecheck` + `build` + a local **`--sync` dev** run are **NOT sufficient** — every one of those was green for the broken v0.4.1. **THE hard-won agy invocation rule (the path everything hinges on — every flag verified live):** invoke **bare `agy --print <prompt>`** with the worktree as cwd — **NO other flags, stdin closed.** Two non-obvious failure modes, each cost a debugging cycle: **(1) agy surfaces its own argv flags into the model's context, which trips its built-in `antigravity_guide` skill and derails the run into *explaining the flag* instead of working.** `--dangerously-skip-permissions` made it lecture about that flag (exit 0, **zero edits — a silent no-op / fake-success**, the most dangerous failure for our PR-gated review flow); even `--model <name>` made it announce the model and stop, or hang past a 200s timeout. ## 2026-06-13 — Agent Skills + self-learning (DESIGN / BACKLOG — not yet built)

Founder direction, logged for a future build: NeuraMesh's **compounding-knowledge layer** — agents (and humans) capture reusable, named procedures ("how to do X") that other agents discover and apply on similar tasks, so the team gets measurably smarter over time instead of every agent rediscovering the same things. This is the productization of lessons like #1004 ("how to render HTML for validation on Apple Silicon via the screenshot tool") — that hard-won knowledge becomes a skill the next agent loads in one call.

**What a skill is.** A `SKILL.md`-shaped doc: frontmatter (`name` kebab-slug, `description`/when-to-use, `scope`) + markdown body (the procedure — steps, snippets, gotchas). Deliberately aligned with the Anthropic Agent Skills format the team already uses (this very session runs on it), which buys two things we can explain rather than cargo-cult: **progressive disclosure** (name+description are cheap and always discoverable; the body loads only when an agent commits to using it — the reason that format scales), and forward-compatible import/export with the Claude Agent Skills ecosystem.

**Third memory tier.** Skills complete the spine: tier 1 **blocks** (always-in-context channel state, docs/03 §6), tier 2 **facts** (atomic durable truths, bitemporal, recalled — 0014/0015), tier 3 **skills** (reusable *procedures*, deliberately authored, curated, and *applied* via a tool). Distinct from facts: a fact is "X is true"; a skill is "here's HOW to do Y" — larger, versioned, invoked. Reuses the spine's machinery (recall, extract→reconcile, events, channel-scoped sync) rather than inventing new.

**Scope & ACL.** Channel-scoped by default (ACL = channel registration, like the artifact library, docs/03 §7); promotable to **workspace-global** (human/orchestrator only). Agents working a channel see its skills + global skills.

**Authoring & governance (enforced, not prompted).** Humans author/curate in the Skills screen. Agents self-author via a `propose_skill` tool mid-task and a sleep-time **skill-distillation pass** (sibling to fact extraction) → land as **draft**. A curation gate promotes draft→active (orchestrator/human, mirroring library curation); **dedup** reconciles a proposed skill against existing ones by description/vector overlap (reuse the fact extract→reconcile logic) so agents *update* an existing skill instead of spawning near-duplicates; **versioned** with bitemporal validity + `superseded_by` (reuse the facts pattern) — recall surfaces only *active* skills. Append-only events: `skill.proposed | promoted | updated | deprecated`.

**Consumption.** Context-assembly surfaces relevant skills' name+description for the task (cheap, like the channel block); agents pull bodies on demand via `load_skill(name)` and discover via `search_skills(query)` (hybrid FTS+pgvector+RRF — reuse recall). Humans search + preview (Md render, reuse the validation-preview pattern).

**Storage/sync.** A `skills` table (workspace, channel_id nullable=global, name, description, scope, body, status, author_kind/id, version, superseded_by, server-side embedding) synced **channel-scoped via PowerSync** — skills are *team knowledge = cloud truth* (unlike agent logs, which are local-only because they hold tool I/O/secrets). Bodies are bounded markdown and must hold no secrets (same posture as everything synced); embeddings stay server-side.

**Surface.** A **Skills** view per channel (Chat / Board / Library / Memory / **Skills**) listing channel + global skills, searchable + previewable, reachable from the menu — matching the per-channel framing and the Library/Memory precedent. (Open at build: per-channel view vs a top-level nav item with a channel filter — lean to the channel view.)

**Phasing (smallest vertical slice first).**
- **Slice 1 — shared skill library + consumption** (core value, no autonomy yet): `skills` entity + schema + scope + human authoring + sync + search (recall) + preview + agent read/apply (`search_skills`/`load_skill`).
- **Slice 2 — self-learning**: `propose_skill` tool + sleep-time distillation + curation gate + dedup/versioning.
- **Slice 3**: a lighter per-task "learnings" capture if it proves distinct from facts; skill-usage telemetry (which skills get loaded, by whom) feeding curation — surface the valuable, retire the dead.

**Risks & mitigations (first principles).** Skill pollution → curation gate + dedup. Staleness (a skill that was right goes wrong when the repo changes) → versioning/deprecation/bitemporal; recall surfaces active-only. Context bloat → progressive disclosure (name+description cheap, body on demand — the whole reason the format works). Cross-team prompt-injection via a malicious/wrong skill body → curation gate + human-gated global scope + no-secrets rule. Over-engineering → v1 is *authored markdown + discovery + load-into-context*, NOT a skill-execution runtime; steal the SKILL.md mechanic because we can explain why it works, nothing more.

**Litmus (CLAUDE.md #1):** makes the loop's EXECUTE faster and more consistent and compounds the team's competence across tasks — clear pass. Builds on memory spine (docs/03 §6), library curation (§7), recall (0014). Naming/format align with Anthropic Agent Skills for ecosystem interop.

## 2026-06-12 — The :8788 fallback wedge — cloud mode must never bind a harness port

Live failure (user zero, second occurrence of "agents not responding"): sync froze at `last=21:47:13Z` — the exact minute the engineering harness tore down its temporary :8788 control-api. Root cause chain: `ensureApi` fell back to `http://127.0.0.1:8788` when the embedded API didn't come up → the cloud app silently bound to a HARNESS process pointed at a throwaway Docker database → when that process died, `uploadData`'s fetch started throwing **connection errors, which had no logging** (only HTTP-status failures logged) → PowerSync retried the write forever and held back checkpoint application → downloads wedged: agent replies stayed in the cloud, machine presence went stale, and agents showed green off stale status rows. Fixes, all structural: (1) **no :8788 fallback outside dev mode** — embedded-API boot failure in cloud mode retries our own process with backoff while writes queue offline-first; an explicit `NM_API` override still works but logs a loud `api_override` warning so a stray env var can't hide; (2) **uploadData logs connection-level failures** (url + error) and refuses to run before the API URL exists; (3) **`sync_status` logs transitions only** — the uploading-flap spam was burying the diagnostics; (4) **queued writes surface in the status pill** ("● synced · N writes queued") — a queue that won't drain is now visible product state, not a hidden wedge; (5) **agent presence is derived, not stored**: an agent renders online (and "is typing") only while its machine's heartbeat is fresh (<90s) — status rows from a dead host can no longer claim liveness. Same arc, chat affordances from founder review: message-list skeletons until the channel's first watch result (no stale flash, no premature "no messages" empty state), and follow-the-conversation scrolling — smooth animate to bottom on new messages when the reader is at the bottom or just sent, never yanking someone who scrolled up to read history.
