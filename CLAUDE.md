# NeuraMesh — Agent Operating Doctrine

You are working on **NeuraMesh**: the world's best collaboration platform for engineering teams made of humans and AI agents. Full doctrine: [docs/05-engineering-philosophy.md](docs/05-engineering-philosophy.md) — read it before substantial work. Architecture: [docs/02](docs/02-architecture-options.md) (Option A — Electron + PowerSync + Supabase + Hono, chosen 2026-06-10) — and **[docs/09](docs/09-system-architecture.md) for how it actually runs end to end** (read this before touching sync, the command handler, the agent daemon, or releases). Protocol/FSM/memory: [docs/03](docs/03-protocol-and-memory.md). Plan: [docs/04](docs/04-build-plan.md).

## Non-negotiables (the distilled NeuraMesh Way)

1. **Litmus for all work:** does it make the loop (plan → fan out → execute → validate → review → accept) faster, safer, or more delightful? If none — don't build it.
2. **Speed you can feel.** Budgets are bugs when missed: send <50ms · view switch <100ms · cold start <2s · recall <200ms · **agent overhead vs raw Claude Code <10%** · 60fps lists · offline reads+queued writes · motion ≤150ms.
3. **Evidence over claims.** Done = code + failing-test-now-green + evidence artifacts (screenshots/perf numbers/repro) + docs updated + budgets measured + review passed. "Works on my machine" is not evidence.
4. **Enforced, not prompted.** Invariants go in the server/schema/types, never in prompt etiquette. Illegal FSM transitions, double-claims, self-review, artifact-less submit: must be *impossible*, not discouraged.
5. **Your compute, cloud truth** (amended 2026-08-30, was "local compute"). User code/keys never leave machines the user owns — a laptop, or a **cloud machine NeuraMesh provisions for that member** (gVisor pod, its own volume, vendor logins on it, outbound-only, no platform SSH, no platform snapshots of the volume). BYOK/BYOS, owner grants; the platform holds no repo tokens and no model keys — the one narrow exception is the metered **starter brain**, whose key lives server-side and never reaches a machine. Team state is always cloud-consistent + locally replicated.
6. **First principles.** State constraints → derive → check convention → write down deviations. Steal mechanics only when you can explain why they work.
7. **Surface assumptions before building.** "Assuming X, Y, Z — correct me or I proceed." When spec and reality conflict: stop and ask. Silent guessing is the unforgivable sin.
8. **Confirm requirements before executing; work in your task's worktree; smallest vertical slice; commit at working checkpoints.**
9. **No silent scope creep.** No drive-by refactors, no "while I was here," no clever-where-boring-works. Match the codebase's idiom; comments only for constraints code can't express.
10. **Report faithfully.** Failing tests reported with output; skipped steps named. Both themes (graphite dark / cream-oak light) verified for any UI work — it must look beautiful in both.
11. **Every word a person reads is ASD-STE100.** Simplified Technical English governs ALL user-facing text: product UI (labels, empty states, errors, onboarding, notifications), marketing pages, and agent-authored copy. **No em dashes and no semicolons** anywhere. Active voice. Simple tenses only, so "is running" becomes "runs" and "has shipped" becomes "shipped". No `-ing` verbs and no phrasal verbs. One idea per sentence, about 20 words for an instruction and 25 for description. Noun clusters capped at three words. Keep the articles: a clipped fragment reads as ambiguous, not brief. One word, one meaning, reused. Product nouns stay (workspace, room, agent, credits); the ~900-word STE dictionary does not apply. **Say less, not smaller:** a section with a clear title needs no explanatory line under it, and a control that names its own action needs no caption. Delete the subtext instead of shrinking it.
12. **Design is a contract.** [docs/33](docs/33-design-system.md) is the design system: the frame model, three surface strata, tokens, motion, and the etched traps. Any user-facing feature beyond a simple text change gets a **design review before implementation** (board work: the docs/14 design gate; everything else: a mockup or preview-harness round, approved first). New tokens/idioms land in docs/33 in the same PR or don't land.
13. **Place every feature before you build it** ([docs/45](docs/45-feature-placement.md), 2026-09-19). The desktop app is open source and ships on a slow, human-gated, two-repository lane, so it changes **only when asked or when installed apps need it** (a Free feature, a fix installed apps need, or a parity catch-up). Every new feature is placed first, in its plan and in its PR (`## Placement`): the **tier** (Pro = the hosted side, the default · Free = the local app · both = the substrate) and, for Pro, the **plan** (`cloud` only behind a `handler.ts` guard, or every hosted plan: a free hosted workspace rides the same surfaces under the docs/07 caps), the **surfaces** in priority order (Pro: the browser client, then the phone, then the API and the cloud machines as the feature needs · the desktop as needed), the **gate** that keeps a Pro feature inert on a Local connection (`connection.kind` + `workspaces.plan`, server truth, never `IS_WEB`), and **proof per surface** (each surface's automated check + screenshots in both themes, one Evidence block per surface the classifier names, plus the ones you add). The browser client IS the desktop renderer on the web bridge, so a web screen is a public source change either way: what differs per surface is the gate and the release lag. A feature live on the web or the phone that no published desktop carries gets a row in the **[desktop parity ledger](docs/desktop-parity-ledger.md)** in the same PR, and the version-bump PR of the desktop release that carries it closes the row.

## Project facts

- Board FSM: `backlog → todo → in_progress → in_review → done → accepted → closed` (+ `blocked`; plan gate `todo → planning → plan_review`; design gate `todo → designing → design_review → planning`, [docs/14](docs/14-design-stage.md)). **Backlog = parked ideas** ([docs/15](docs/15-backlog.md)): any teammate may park one (`task.create backlog:true` — the ONE agent creation path; worker tool `add_backlog_item`; Rex tools `add_backlog_item`/`list_backlog`/`promote_backlog_item`/`update_backlog_item`), items stay editable pre-work (`task.update_details`, humans/orchestrator, backlog+todo only) with context/images in their thread, daily summaries carry the tally — and **only a human or Rex promotes** (`task.promote → todo`); no agent can offer/claim/design/plan/block a parked item, by construction. Review auto-dispatches to the channel reviewer pool; acceptance is human (per-channel auto-accept policy allowed). **User-facing work is designed first**: the orchestrator triages it to the channel **designer**, whose mockups (self-contained HTML, studied from the repo's real design tokens) render inline in the thread; `approve_design` is HUMAN-ONLY, and the approved round becomes the visual contract the architect plans against, the developer builds to (materialized in `.nm-evidence/design/`), and the reviewer gates on — it auto-promotes into the channel artifact library.
- Agent contract: **A2A 1.0** (Agent Cards; board task = product entity, each work/review attempt = an A2A task sharing `contextId`).
- Thread-per-task; **a channel is a folder of sessions** ([docs/35](docs/35-sessions-shell.md)): a session = a chat thread or a task thread, one row anatomy (a task row wears its phase dial), and a room **opens to its session list** grouped Today/Yesterday/This week/Earlier — crew clusters top-right, Board still a tab, marketing keeps Calendar/Library (the room-scoped twins of the workspace destinations, exactly as Tasks is both). Home is the same rows unscoped (workspace-wide) + the needs-you queue + New chat (⌘N); opening a session takes the whole main surface with a back crumb, so the thread sheet-over-feed dies. The orchestrator's **digests and announcements are room-brief summary cards** pinned at the top of the room home; the feed retires as a surface, and the docs/20 threads-off lens is **absorbed** — a room already shows its threads, so `channels.thread_mode` stays server-side and unread (its digest hush deleted, or a stale `'off'` would silently suppress that room's brief). No schema change: `threads` + frozen `mode` + `root_message_id` + thread-per-task already model sessions. **Workspace Files** (the Library, renamed 2026-08-07, [docs/design/workspace-files-2026-08](docs/design/workspace-files-2026-08/plan.md)): the nav destination is **unscoped** — root is a folder per project (its own logo, its rooms, and an **access row** of the agents that can read it), one level down is a typed file table. Curation is a **marker, not a gate**: the destination stopped filtering `promoted = 1` (which made the marketing bootstrap's brand docs structurally invisible while three other surfaces and the agents' own `list_library` showed them), so the ★ now means *a human shelved this* and `Documents · From tasks · ★ Shelf` are chips. **ACL = channel registration, unchanged and now visible**: a file belongs to a room, uploads pick that room out loud (the picker names its readers), and uploads ride the `artifact.create` command — never a local row, because the ps_crud artifacts branch is gated on `message_id` and would drop it. Agents read via `list_library`/`read_library_doc` with `scope: room` (default, the ACL) `| project | workspace`; images return a typed stub, never base64.
- **Chat mode** ([docs/34](docs/34-chat-mode.md)): **the Tasks toggle RETIRED** (§14, 2026-07-29 — the orchestrator decides; every new thread births `tasks`; §14a: the human's explicit word creates in place via the backlog trio). `threads.mode` survives as the enforcement floor only. Legacy `chat` threads answer **in the thread** with real tools — live web research inside the reply, files written in a per-conversation scratch workspace that render inline (docs/30), commands under the existing kernel jail + policy gate — and **nothing reaches the board**. The mode lives on `threads.mode`, frozen at the thread's birth and moved only by a human (`thread.set_mode`, HUMAN_ONLY) — the escalation valve that turns a chat into work **in place**. Enforced twice, never by prompt: the chat turn is built from a registry with no `create_task` in it, and the server rejects `task.create` naming a chat thread (`CHAT_THREAD`). The mode belongs to the THREAD, so any agent woken there answers conversationally (default responder = the last agent who spoke, then the orchestrator); no `nmq` cards in chat — a conversation asks in prose rather than filing an item in the needs-you queue.
- **A deliverable you can produce is not a task** ([thread-posts](docs/design/thread-posts-2026-08/plan.md)): **drafted social posts are thread-native**, in ANY room. `content_items` anchors on `thread_id` **or** `task_id` (0115), agents hand drafts over with `draft_posts` (never a `posts.json`, never pasted markdown) and rewrite them **in place** with `revise_posts` by card letter, and the same `SocialPostCard` — approve · schedule · request-changes · per-network preview — renders in the conversation thread and the task panel from one derivation (`postCardsFrom`). The old "propose a content task, then offer it to the marketer" note is DEAD: it beat the general triage rule, and declining its card left the orchestrator with no move, because a card could only exist on a task. Nothing here is gated on `channels.kind = 'marketing'` — publishing resolves its connector through the channel's **project** (0106), so the room's type only ever decided who was told they could. A content ask reaches the board on the normal bar only (they asked, or it must outlive the conversation). **Agents draw, too** ([agent-images](docs/design/agent-images-and-calendar-2026-08/plan.md)): `generate_image` (re-runs the brief on the card) rides the orchestrator + chat registries, and `revise_posts` with a new `imageBrief` REDRAWS — both wrap the LLM-free `generateDraftImage`, drafts only. Before them the only caller was the `‹gen-image:›` marker the card's button emits, so an agent asked for a picture could only point at that button — a tool inventory beats a prompt rule, every time. The card matches: a picture already on a card gets a **redraw** icon (the `wantsImage` predicate began `!media?.thumb`, so every image control vanished the moment one landed).
- **Setup flows** ([docs/39](docs/39-setup-flows.md)): a channel kind's guided first-run is a **task you can abandon** — creating a flow-bearing room (marketing today; the registry `shared/setupflows.ts` is data) plants ONE `kind='setup'` task (partial-unique 0117, closed rows keep the slot), living the lean `finish`/`cancel` life: no agent can offer/claim/plan it, `task.create` can't mint the kind, stall/staffing skip it. Steps write as they land (`setup.step`, HUMAN_ONLY → `setup_progress`), so the wizard resumes; completion = the flow's completing command (`marketing.setup`, now MERGING the profile), which stamps `setup_at` — the one "ran to the end" every surface gate reads (`marketingReady()`, never presence). Open setup = needs-you until finished/cancelled; done setup never queues (no accept exists). Backfill: `setup.backfill` at daemon boot, untouched-profile rooms only. New projects default `general+build+marketing` (research off); a starter `marketing` room is marketing-KIND.
- **Whiteboards** ([docs/38](docs/38-whiteboards.md)): Excalidraw scenes as synced rows — the pre-task thinking surface and the agents' one diagram surface (the design gate's studio stays the visual contract; boards shelve in the Whiteboards destination, never the artifact library). Nav destination beside **Tasks** (the Board label renamed 2026-08-05 — label only, ids/FSM/docs keep `board`); the sixth workspace-tab kind (the canvas keeps its own chrome, assets self-hosted, zero egress); share posts a `‹wb:id›` marker message both thread renderers swap for the snapshot card — tiles and cards render stills, never live canvases. Two write lanes: humans local-first, LWW-by-rev (a stale autosave ACKs `applied:false`, never wedges the upload queue); agents on the strict `whiteboard.create/update` command lane (`WHITEBOARD_STALE` on a lost race). Agent tools `create/update/list/read_whiteboard` ride every registry (mermaid flow/sequence/class arrive EDITABLE, other kinds as one image; element-skeleton JSON strings for precise layouts); reads are workspace-wide, chat turns draw by design, triage/legs read-only — and the daemon never renders: the first desktop to mount a sourced board materializes it (rev-guarded, one winner).
- **Worktree berths** ([docs/40](docs/40-worktree-berths.md)): a task worktree is **cache, not home** — berth class derives from the board (leased = active/blocked/unknown, untouchable · warm = submitted, evictable newest-kept · dead = settled, removed TOTALLY: dir + git admin entry + local branch + subject brain), one **berth sweep** owns `cache/` (boot · 6h · post-reclaim · Reclaim-now; `NM_WARM_BERTHS`/`NM_CACHE_BUDGET_GB`), and **donors** make eviction ~free: `node_modules` stashed per (repo × lockfile-hash), CoW-hydrated before the agent ever types install (kernel `clonefile`, 2.99 GB in 1.5 s at ~30 MB marginal; CoW-or-skip, gitignore-guarded). The **agents' footprint** (Home card + `'footprint'` destination) is machine truth over IPC: apparent sizes said out loud, the sweeper's own verdict as "reclaimable now", third-party agent dirs **reported, never touched**; chart series ride the validated `--viz-*` tokens (docs/33 §4). Spawned git in harness modules strips hook env (`gitChildEnv`) — `git commit` exports `GIT_DIR` to hooks and a leaked one re-inits the OUTER repo.
- Code-surface boundary: NeuraMesh **reads, reviews, and runs** (review cockpit: artifact-rendered diff viewer + task file tree; per-task mini terminal — **on the desktop today, and in the browser via nm-relay**, below) — it never edits. Diffs render from artifacts so review works cross-machine and offline; quick fixes bounce to the agent or deep-link to a real editor.
- **The GitHub connector** ([docs/44 §the GitHub connector](docs/44-release-drafts.md), design [github-connector-2026-09](docs/design/github-connector-2026-09/plan.md), 2026-09-19): a `connectors` row `provider='github'` per project (handle = the repository slug, no secret) is the ACL that lets the room's agents READ the project's primary repository through the platform's GitHub App (`/v1/repo/changes|file|tree`, a per-read installation token, never on a machine, never stored); the row is written by the sealed-state install callback or `POST /v1/github/resolve`, and **the grant is the first move** (2026-09-20): the step never demands a repository, GitHub's install page is where the person picks the repositories, and the repository comes back with the grant (one attaches itself to the project, several show a pick in the step; `repoForChannel` reads the GitHub-addressed repository, so a desktop's local folder never blocks a read). Three tools ride every registry (`list_repo_changes` · `read_repo_file` · `list_repo_files`, one reader `host/reporead.ts`: the connector, else the machine's `gh`, else the refusal that names the fix), the release tick reads through it on a cloud machine, and `run_playbook('release')` refuses with **Connect GitHub** on the card when nothing can read, and reads the digest at creation into the unit when something can.
- **The browser terminal + nm-relay** ([docs/42](docs/42-browser-terminal-and-relay.md), live 2026-08-30): machines never listen (outbound-only, non-negotiable) and Vercel cannot hold a stream, so a browser has NO path to a machine — `nm-relay` is the rendezvous both sides dial OUT to, stateless and keyless (control-api validates both credentials over `RELAY_SECRET`). It is what makes **vendor logins on a cloud machine** possible at all (`claude setup-token`, `gh auth login` must complete in the vendor's own flow, on a machine you own), which is the thing cloud-first was actually blocked on — the terminal pane is the visible half. Four traps live in the doc and are easy to re-introduce: **exactly one replica** (routing tables are in-memory; two replicas report `MACHINE_OFFLINE` for a machine that is online), **two health checks** (the LB's default probes `/` and fails while the kubelet's `/healthz` passes — a `1/1 Running` pod behind `503`), a **30-second default WebSocket backend timeout** without `GCPBackendPolicy`, and **bytes-not-strings** (a pty's multi-byte characters split across frames; one streaming decoder per channel, and `btoa` throws above U+00FF). Unset `NM_RELAY_URL`/`VITE_NM_RELAY_URL` degrade to the honest "No shell here", so the lane is additive. **Never pin a machine image you have not watched boot** — the image now imports `machined` at build time, because a missing workspace `COPY` is not a build error under pnpm and took the fleet down once with every check green.
- Projects are first-class — the *work axis* and top-level container: **Workspace → Projects → Channels** (a channel belongs to **one** project, `channels.project_id`; 1:N). **Exactly one project is active at a time**, switched from the top-left, scoping the channel list and the room the shell is standing in. It no longer scopes the DESTINATIONS (2026-08-07): Tasks · Whiteboards · Automations (› Routines · Calendar) · Files · Skills · Activity are **workspace-wide**, each carrying a **scope bar** (search + project + room) so narrowing is a visible, reversible choice rather than an invisible default — the same ruling as the Files ★. **Automations is the one destination with two surfaces** ([docs/design/agent-images-and-calendar-2026-08](docs/design/agent-images-and-calendar-2026-08/plan.md)): Routines is the inventory of what is armed, **Calendar is the time view of everything scheduled** — automation firings (projected through the shared `nextScheduleRun`, never re-derived) *and* drafted/scheduled posts, in two lanes. Its children nest in the NAV; a destination never grows a tab strip (docs/33 §8). The calendar stopped being gated on `channels.kind='marketing'` + a finished setup flow, which had made it unreachable from anywhere but one room — the Files `promoted=1` bug class; the marketing room's own Calendar tab stays. Memory is the exception by construction: `/v1/memory` is keyed to one channel, so it gets a room picker, not an aggregate. Channels are the *rooms* + the **ACL boundary** (agents register to channels; an agent sees a task via its channel, not its project). One **default project per workspace** holds the starter channels = zero ceremony; repos attach to projects; a **task's project is its channel's project** (derived). Humans manage projects in the switcher (create/rename/archive, move channels in) and **channels from the channel list** (create via the `+` by the Channels header; rename/delete via each room's settings gear — rename edits slug + topic, safe because a channel is identified by its id; delete is type-the-name-gated and purges the room's messages/tasks/history); the orchestrator's `create_project` makes one for a new initiative **only after confirming with the human via a question card** (it doesn't create projects silently). Orchestrator **staffing follows add-before-hire**: when nobody in the room fits the work, it proposes adding an existing workspace agent (add card) before proposing a new hire (hire card → `create_agent`) — both human-gated; hires carry a stored specialty **`brief`** injected into their task prompts; orchestrator/curator are never hireable; re-registering a retired name is a rehire. Full taxonomy: [docs/06](docs/06-taxonomy.md). Milestones / dashboards / workspace-library = phase 2.
- Git flow: tasks carry project + repo + base + branch `nm/<id>-slug`; for repo-backed tasks **submit = artifacts + branch pushed to remote + a pull request opened (`gh pr create`), review pinned to the submitted SHA** — acceptance is machine-independent (fetch the branch anywhere). The reviewer gates on the PR's **CI** (`gh pr checks`: failing/pending → request changes; no CI → proceed) plus the diff against the Definition of Done; **the PR is squash-merged to its base only on `accepted`** (a host watch runs `gh pr merge --squash --delete-branch`) — reached on the human's WORD (2026-09-08: Accept is no longer a button anywhere — the human says "merge it" in the task's thread and the orchestrator's `accept_task` applies it; the server refuses an agent accept without a HUMAN message in that thread newer than the review verdict), or by the shipper's server-verified `execute_ship` under a human-approved release plan — code never reaches main by direct commit. v1 uses the machine's own git/`gh` creds; the platform never holds repo write tokens (GitHub App + short-lived tokens for remote agents = phase 2). **Landing from a worktree: use `scripts/pr-land.sh <pr>`, never `gh pr merge --delete-branch`** — deleting the branch you are standing on makes gh check out `main`, which the primary clone holds, so it prints `fatal: 'main' is already used by worktree` AFTER the squash has already landed. The exit code is not the answer either: ask the API whether the PR merged (the script does).
- **Plan-first units + thread-owned work** ([docs/41](docs/41-plan-first-units.md), 2026-08-17): **every unit of work starts with an implementation plan the human reviews in the unit's own thread before anything is built.** rex **creates directly** (`create_task`, plan required — the proposal card retired 2026-08-17; server refuses plan-less agent creates) with the plan (declared journey `legs` ⊆ design→build→review · proposed subtasks · approach); the unit is **born in `plan_review`** (inert until approval) (`tasks.work_plan` jsonb) **anchored to its conversation** (`tasks.origin_thread_id`, N:1) with a `‹task:id›` **unit card** in the thread (click = the peek; an anchored unit NEVER earns a session row). `approve_plan` (HUMAN_ONLY) releases it: confirms requirements, mints the subtasks, and the legs route themselves (design-first → the `planroute` watch fires `request_design`; build-first offers claim). Floors: build always · causal order · **repo-backed ⇒ review, non-declinable** · a claim can't skip a declared design leg · accept always human. Lean units (no review) `finish` to the accept gate, deliverables on themselves. Revisions (`revise_plan` → `propose_plan` with legs/subtasks) ALWAYS clear the approval. journeyFor renders declared legs (plan leg first); `propose_impl_plan` plans promoted/board-born todos. PowerSync: none.
- **Subtasks + phase spectrum** ([docs/24](docs/24-subtasks.md)): companion work rides its parent — `task.create parent:` (ANY teammate; rex/worker `add_subtask` tools; the panel's add box) makes a task row with `parent_task_id`, folded under the parent's board card (never its own), living the lean `claim → finish → cancel` life (`finish` by assignee **or any human**, straight from todo — no subtask can block; cancel is the other valve). Parents refuse `submit/accept/approve_ship_plan/execute_ship` with open subtasks (`SUBTASKS_PENDING`); deliverables attach to the PARENT (`finish_subtask`); agents creating a peer task that names an open task get `MAKE_IT_A_SUBTASK`; **phase subtasks are banned** — the **phase spectrum** (shared `journeyFor`, derived from FSM state + routing evidence + live roster + beats, never stored) is the journey view: panel-header bar with hover names, 4px board-card whisper, unstaffed legs dashed. **The task panel is zoned** ([docs/25](docs/25-task-panel.md)): header = identity + spectrum + a facts line of toks (`✓ reqs · artifacts n · subtasks x/y · PR #n`, warm when holding a gate) → at most ONE drawer under the tabs; thread owns the middle; exactly ONE contextual gate card docks above the composer (a working state docks nothing); the beats tracker rests as a one-line ticker (hidden while a gate shows), expanding to full docs/17 sets on click.
- **Ship stage** ([docs/23](docs/23-shipping-stage.md)): the release gate between reviewer-approve and merge. In a ship-gated project (`projects.ship_gate`, default ON, null-safe) the channel **shipper** (default agent **bosun 🦭**, seeded at onboarding + boot-backfilled like iris) claims a reviewer-approved PR task (`done → shipping`, the claim IS the cross-machine dedupe), studies the change (PR `## Deploy notes`, host-settled CI, the pure `shipscan` diff scanner whose findings map onto the Deploy-notes taxonomy, repo release docs, lessons, the bundled shipping skill), and proposes a **release plan** — a `ship` artifact report + an owner-tagged checklist on `tasks.ship_plan` (jsonb, command-mutated, zero PowerSync work). `approve_ship_plan` is **HUMAN_ONLY** (Mission Control + phone push); owners tick their items (`check_ship_item` — an agent can NEVER tick a human item); `execute_ship` fires only when every item clears (`SHIP_ITEMS_PENDING` otherwise) and lands in **`verifying`**, where the verifying watch squash-merges, then proves the release landed — post-merge CI on the merge commit + triggered release workflows, pure verdict in `shipverify.ts` — before `confirm_release` earns `accepted` (red verdict = one 🔴 thread alert + hold; human Accept overrides, `request_changes` bounces a fix-forward round). The proposal message names **`ship-plan-vR.md`**, which linkifies into the same block-comment review overlay as implementation plans (comment → one `revise_ship_plan` round; approve inline). The direct human accept stays legal from every ship state (paved road, never a cage). Scratch/non-PR tasks skip the gate by construction.
- Definition of Done: every task has an editable **`definition_of_done`** — the authoritative acceptance contract the reviewer gates on (architect writes it into the plan's `## Definition of Done`; orchestrator sets it at offer otherwise; humans edit it in the task view). For code work it encodes the PR flow, never "commit to main."
- Stall watchdog ([docs/19](docs/19-stall-watchdog.md)): the daemon's sweep tick (15-min + ~90s after boot) deterministically flags stuck work by **absolute age** (`stall.ts` — feedback sitting unactioned on review gates, dead active phases, unclaimed offers, stale blocked/waits; open decision cards + live local flows suppress; one firing per signal, capped 5/sweep), then the orchestrator triages: relay the human's implied verdict (`revise_design`/`revise_plan`/`request_changes`), re-offer unclaimed offers, or escalate via an `nmq` question card. Detection is code, action is judgment; echo mode stays inert. Beats re-attempts declare **rework-named, round-aware titles**, and every tracker set minimizes/expands from its title row (docs/17).
- Releases & deploy: [docs/11](docs/11-releases.md). Backend ships continuously (merge to main → Vercel → migrations auto-apply + bundle auto-regen); the desktop app is tagged `vX.Y.Z` → signed DMG → **draft** in the public releases repo → the human publishes. **Backend before desktop**, always. **Any PR needing a manual step on/after deploy — a PowerSync re-snapshot, a new Vercel env var, a manual backfill, publishing the desktop draft — MUST spell it out in its description under `## Deploy notes` (the PR template pre-fills it).** Silent manual requirements are the v0.5.0-class failure. **Sync-rule deploys are automated** (`powersync-sync-rules.yml`, since #196) — but that job **no-ops green when its secrets are unset** and its PR-side `validate` is advisory, so confirm the run's `Deploy sync rules … → success` **step**, never the check's ✓.
- Memory: own pgvector spine (summary blocks, extract→reconcile facts, bitemporal validity, hybrid RRF recall). **Semantic legs are live wherever the API runs local** (`NM_EMBED=on` in the launch scripts — bge-small ONNX warmed at boot, NULL embeddings backfilled at boot; **Vercel stays FTS-only by design**; reconcile supersedes only near-paraphrase, <0.1 cosine); worker context packets carry top-k recall hits at fan-out; budgets + measured decomposition in [docs/18](docs/18-performance.md). **Lessons** = facts with `kind='lesson'` + task provenance, born from review corrections: any teammate writes via `memory.record_lesson` (worker `record_lesson` tool; post-approve mining covers tool-less runtimes), injected into worker + reviewer prompts so a corrected mistake is not repeated. - **The public repository** ([docs/43](docs/43-public-repository.md), 2026-09-14): `neuramesh-ai/neuramesh-oss` is a **publish** of this one, the desktop app and what it needs to run, open source under the Elastic License 2.0. `scripts/public-tree.sh` is the ONE list: `PUBLIC_EXCLUDE` is what stays private (the site, the phone app, the cloud platform, the pipelines, their identifiers, every design round's `evidence/`), and **`PUBLIC_DOCS` is the docs that ship: a new document, folder or design round under `docs/` is PRIVATE until a line names it** (2026-09-19; `bash scripts/public-tree.sh --private` lists what a publish would leave out, and the scan says it on every PR); every push to `main` snapshots, scans, and opens the public pull request a human merges; a contribution is ported here with `git am` and rides the next publish. A tag never rides the publish: the public commit is tagged from a public clone for the control-api image, the private tag builds the desktop draft, and the image must exist before the desktop that pulls it is published. **A desktop release is cut as needed** (docs/45 §4), never per feature: Pro work lands on the web and the phone first, and the ledger says what the newest desktop does not carry yet.
- **Every change is proven on the surface it reaches** (2026-09-19, after #548 took the live web app down at boot with every unit suite green): `surface-e2e.yml` runs `scripts/impact.mjs` on every pull request. It classifies the diff into **web · desktop · mobile · cloud · api** (rules are data in the script: a shared package reaches every client, the daemon reaches the desktop AND every cloud machine, a doubtful path implicates rather than exempts) and runs the check each surface needs. **web** boots the BUILT browser client in real Chrome to its first screen (`scripts/web-boot-e2e.mjs`, Chrome over CDP, no Playwright, `stuck` on the exact #548 class). **mobile** typechecks and tests the phone app. **cloud** says on the run that the change reaches the machines on the next release tag (`fleet-roll.yml` builds the tagged commit's machine image, pins main to it and deploys) or a hand pin between tags. **api** is `ci.yml`'s pg lane. **desktop** is `local-stack-smoke.yml`. A change to the classifier or a probe re-runs everything. Run any of it by hand: `node scripts/impact.mjs origin/main`, `node scripts/web-boot-e2e.mjs`. **The classifier's verdict is the floor of the PR's Evidence** (docs/45 §5): one block per surface it names, with the check's output and screenshots in both themes for a surface with a screen, and the author adds the surfaces the classifier cannot see. A surface with no block is not done.
