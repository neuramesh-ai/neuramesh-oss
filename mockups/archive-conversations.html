1 · Archiving, from the row it happens on

A conversation is archived from its own row — the same gear-on-the-row idiom the channel and project rows already use, revealed on hover so a resting list stays clean. Archiving takes it out of Recents and out of the room's session list immediately; a brief Undo covers the misclick, because the alternative is a confirm dialog on something that is not destructive. Try the ⋯ on any row.

3 · The choices worth making

Chat threads onlyRecommended

A task thread's life belongs to the board — it ends at closed. Letting a task thread be archived would put two different lifecycles on one surface. Task rows get no archive action.

…or anything in the list

Consistent per-row behaviour, but a task you archive is a task that silently stops appearing while the board still counts it open.

Undo toast, no confirmRecommended

Archiving is reversible and non-destructive, so it shouldn't cost a dialog. The row leaves at once and Undo sits there for a few seconds.

…or a confirm dialog

Safer for a truly destructive act — which this isn't. It would make the common case (tidying a long Recents list) needlessly slow.

Delete is deliberately absent. You asked to archive, and archiving keeps the record: an agent's work, its artifacts and its memory all still reference that thread. A real delete would have to decide what happens to those — worth its own round if you want it.
