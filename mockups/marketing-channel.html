The marketing channel — rooms get a trade

Channels have always been function rooms (docs/06: #dev, #marketing, #research — and a #marketing agent can never receive engineering work). This proposal makes the function real: a channel carries a kind, and the kind picks the room's interface and toolbelt. kind='build' is today's product, untouched — the seeded #dev room is renamed #build for new workspaces. kind='marketing' turns the room into a growth HQ: a setup card, a crew that studies your product and writes the brand docs, a strategy you arm with one tap, a content calendar, and a library. Two rules the design encodes: a kind is a lens plus a toolbelt, never a new silo — same rooms, same channel ACL, same task FSM underneath; and agents draft, humans publish — nothing leaves the building without an explicit approve or a policy you set yourself.

The pill is the hire-card pattern, not a hidden verb. A tap opens the when-picker; Arm schedule posts a visible confirm into the thread and writes one schedules row. Agents can propose schedules (a card), only humans arm ones that touch the outside world. On Free the same tap opens the full-powers gate — this is THE upgrade moment (server-enforced: schedule.create → PLAN_LIMIT).
schedules is generic from day one — workspace-scoped, channel-anchored: cadence (once|cron), next_run_at, agent_id, payload (prompt/skill), run_count. Build rooms get it later for free ("nightly triage sweep") — the calendar UI just ships in marketing first.
Execution is the daemon's new minute-tick beside the 15-min sweep. Claiming a due run = an atomic run_count advance — counter, not timestamp (the ship-stage lesson), so two machines never double-fire.
Laptop closed = run missed — surfaced as missed on the row and flagged by the stall watchdog, never silent. A cloud runner is the phase-2 answer.

Click any chip → this preview. Scheduled chips get Approve · Edit · Unschedule; published chips carry the receipt (external_url, who drafted, who approved) — the audit trail is the calendar.
content_items — platform, body, media (artifact refs), status draft→scheduled→published|failed, scheduled_at, external_url, schedule_id, approve audit. Synced; chips are content items, never tasks.
Approve is the accept gate wearing a calendar. content.approve is HUMAN_ONLY (like approve_design / approve_ship_plan); an explicit per-channel auto-publish policy is the paved escape hatch, mirroring acceptance_policy.
Publishing runs server-side (control-api cron; tokens never leave the server) — due + approved → post → write external_url → green chip. Posts fire on time with the laptop closed; failures land a 🔴 thread alert (the ship-verify idiom), never a silent drop.
Surface chips replace the chat/board toggle only in marketing rooms — one kind branch at the App.tsx view switch; build rooms render exactly today's tree.

No new storage system. Docs/drafts ride artifacts.inline_content exactly as deliverables do today; folders = artifacts.tags (column exists — starts syncing). The rail's "Library" and this surface are the same rows.
Big media rides the attachments pattern: full bytes on the machine (userData dir, nm-attachment://), synced thumbnail inline, plan-gated size caps from entitlements.ts. Cloud copy (Supabase Storage / GCS) is the documented phase-2 offload — and a natural Cloud upsell: your media on every device.
ACL unchanged: the library is the channel's artifact library, worn as a first-class surface. The project-level view aggregates its channels' libraries — same rows, wider lens.
.nm-evidence/ stays what it is — throwaway working files, git-excluded. The library is the published home.
07

What it takes

Full plan with slices, migrations and open questions: docs/design/marketing-channel-2026-07/plan.md
Schema: channels.kind · connectors (+ non-synced token vault) · schedules · content_items · sync artifacts.tags. Each synced table: id + publication migration + sync rule + both client schemas (parity test).
Commands: channel.set_kind · marketing.setup · connector.connect/disconnect · schedule.create/pause/delete · content.approve/unschedule (HUMAN_ONLY where it touches the world; paid-gated at the door).
Daemon: minute-tick scheduler + publish watch + marketer role prompt/tools + plume seed/backfill; stall watchdog learns missed schedules.
Desktop: kind branch at the view switch · setup card · HQ rail · calendar · library surface · settings Kind row · upgrade-gate card. Mobile v1: read the calendar + approve drafts from the phone (the Mission-Control needs-you idiom).
