The harness, made visible

What lands on screen when the harness ships: a run tree that nests as deep as the work goes, one narrator for a whole subtree, a parked state for work that waits, permission cards that say which subagent asked, and a brain you can carry to a new machine. Every token here is lifted from tokens.css; every idiom is an existing one, extended.

The one rule this round exists to settle. A turn tree can have twelve agents in it. Twelve narrators is not a feature, it is the regression docs/26 spent a release deleting. So: the parent's run card is the single narrator for its whole subtree — a subagent never mints its own ghost bubble and never its own card. It is a row inside its parent, indented by depth.

4 · Parked — work that waits, and costs nothing while it does

A new non-terminal run state. It keeps its ring, so a parked run still reads as alive; the ring holds its fraction instead of breathing, which is the difference between waiting and working.

Why it needs a shape, not a colour. The runs card is monochrome by design — "SHAPE carries state (pulse / check / bar), the hue stays out of it." Bar was already in that vocabulary, so parked is a pause-bar pair: unmistakable against the pulsing dot (running), the check (done) and the hollow ring (stopped), with no new hue.
The prompt paragraph that gets deleted. Today's worker prompt tells the model "nothing you start survives it… no scheduled check-in that calls you back." When park ships, that stops being true and comes out. This card is what replaces it on screen.
Where it already fits. isRunOpen stays true for parked, so the rail's live row, the run dock, and the phase ring all keep painting it without a change. Only RunMark gains a branch and RUN_STATES gains a member.

7 · Move to a new machine — the one genuinely new surface

Everything above extends a component that exists. This is the exception: a settings flow for exporting a brain, restoring it, and adopting the agents onto the new machine.

step 1 · old machine
Export

Tier A — your agents' ledgers, notes and produced files — as one encrypted archive. A passphrase is required; there is no plain export.

step 2 · new machine
Import

Unpack into ~/.neuramesh. Refuses to land on an existing brain unless you say merge or replace.

step 3
Sign in

Projects, conversations, tasks and artifacts arrive from sync — they were never in the archive, because they were never only local.

step 4
Adopt agents

Re-point this workspace's hosted agents at this machine. Explicit and confirmed — two machines legitimately share a workspace.

TIER ALedgers · notes · produced files · attachments · settingsin the archive
TIER BThe replica and the activity logoptional · rebuildable
TIER CWorktrees · clones · sessions · keychain credentials · CLI loginsnever travels
Two sentences of copy that carry the whole security model. On the export screen: "Your model keys and sign-in stay on this machine. You'll sign in again on the new one." On the adopt screen: "rex, patch and iris are hosted on MacBook Pro (old). Move them here?" — naming the machine that still owns them, because silently stealing agents from a running machine is the worse failure.
