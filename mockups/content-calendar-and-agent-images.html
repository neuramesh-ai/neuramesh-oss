00What actually broke

Two separate failures, neither of which is the one it looks like from the outside. Both are missing seams, not missing features — the machinery to do the thing already exists and runs; nothing is wired to it from where you are standing.

finding 1 Rex cannot draw — it has no hand tool gap

The drawing function already exists, is already channel-scoped, and already needs no model turn: generateDraftImage() in agents.ts:7221. It resolves the designer's image key, reads the brand tokens, calls generateBrandImage, and writes the result onto the card.

The only way to reach it is the invisible marker ‹gen-image:id› — which only the card's own button emits. Rex's tool registry (buildOrchestratorTools, agents.ts:7524) carries draft_posts, revise_posts, schedule_posts, unschedule_posts — and no image tool. Neither does the chat registry. Neither does the shared harness catalogue.

So when you ask rex for a picture, it is telling the literal truth: the only thing it can point at is your button. A prompt rule would not fix this — the tool inventory is the enforcement, and there is nothing in it to call.

Second-order: revise_posts accepts an imageBrief and writes it to the card — then draws nothing. The one place "change the picture" naturally lands is also the one place that silently only writes text.
finding 2 The button did not disappear — it never covers this case gate gap

One predicate decides every image control on a post card (App.tsx:9174):

const wantsImage = !media?.thumb && !media?.image_url
  && !!media?.brief && !superseded;

Read the first clause. Once a card has a picture, every image control is gone — Generate, Try again, the "no model connected" prompt, all of it. There has never been a redraw affordance. Git confirms nothing was removed: the button's only two commits added it and then added a second surface for it.

And a third silent state: while imageReady is still undefined (the credential lookup is in flight, or it rejected) the card renders no image row at all — not the button, not the connect prompt, not an explanation.

Same bug class as the Files promoted = 1 filter: a predicate that makes a real thing structurally unreachable, and reads as absence rather than as a rule.
finding 3 The content calendar is gated on a room's kind reachability

The calendar exists and works. It is reachable only as a tab inside a room that is kind = 'marketing' and has finished its setup flow (room-tabs.ts:40-50). Its query is channel-scoped: nm.contentItems(channelId). So there is no way to ask "what is my workspace publishing this week" — and if you are standing anywhere but that one room, the surface does not exist. Meanwhile every other destination went workspace-wide with a visible scope bar on 2026-08-07. The calendar is the one that was left behind.

If you would rather spend the slot, A is one tuple and no docs/33 amendment, and everything in scene 04 is identical either way.

the three changes and why each one is forced
Unscheduled railToday an unscheduled draft is drawn on the day it was created (scheduled_at ?? created_at, App.tsx:9387) — a calendar cell that asserts something will happen then, when nothing will. Drafts with no slot get their own rail above the grid, which doubles as the marketing half of the needs-you queue: your agents wrote these and they are going nowhere.
Room tag on a chipAt All scope a chip has no other way to say which room it belongs to — and the room is the ACL boundary and the connector's owner. Reuses .routineroom, the tag the sibling tab already puts on a row at All scope, and hides itself when a single room is selected.
Image dotThe one thing you cannot see from a text chip is whether it will publish naked. A 7px square before the body means brief written, no picture yet. It is what makes finding 1 and finding 3 the same round.
KeptPlatform rows, Monday start, the week window, the click-to-preview modal with approve/unschedule/delete. The grid is right; it was just unreachable.

06The workspace with no marketing room

The reason the calendar was gated in the first place: it is meaningless in a repo-only workspace. Gating made it invisible where it was meaningful too. An empty state costs one screen and never lies about where the surface is.

Nothing is queued to publish. Drafted posts appear here the moment an agent hands one over — in a marketing room, or in any conversation where you asked for one. Approve a draft and give it a slot, and it lands on this grid.
What this round does not touch: the publish connectors, the approve-then-schedule gate (still human, still content.approve), the marketing room's own Calendar tab, and the designer→marketer review ladder inside image generation. The drawing engine, the brand-token prompt and the one-redraw review all stay exactly as they are — this round only gives agents a handle on them, and gives you somewhere to stand where you can see the week.
