Live work visibility — when an agent starts something long

The bug in the screenshots: rex promised work he had no way to show, finish, or be held to. A wake is the only unit of work chat has — it opens a stream, paints the ghost (docs/26), posts a reply, and ends. Anything the model "kicks off in the background" dies with that turn: no row, no progress, no fan-out, no delivery. So the human is left asking where are we? while the rail says standing by, and the reply reaches for a foreign affordance (/workflows) because the product has no surface of its own to point at.

The fix is one missing noun: a run — the row every wake already half-has (agent_logs.run_id, beats.run_id) but never writes down. Promote it to a synced table with a parent (parent_run_id), and long work becomes ordinary: it survives the turn, it renders on every machine (today's live status is local IPC — the phone sees nothing), it fans out into legs, it settles honestly, and the watchdog can flag it.
