Agent identity — two fields, two audiences

Round 2, after the founder’s notes. The hover card drops instructions (click through for those), and list_agents must carry a brief of what each agent does so rex can pick one — or decide it needs a new one. That second ask is not a small addition: it means the field has a second reader with a different job, and the research below says every serious agent framework splits exactly there.

So: two fields. description — short, third person, written for the router. instructions — long, second person, written for the agent itself. Today NeuraMesh has one field, agents.brief, doing both jobs badly: capped at 2000 (too long to list, too short to instruct), injected as a system-prompt fragment, and never shown to rex at all.

0 · What the field split should be research

Three independent frameworks, one shape: a routing string separate from the system prompt.

Claude Code subagentscode.claude.com/docs/en/sub-agents
“description · Required · When Claude should delegate to this subagent”
“Claude uses the description to decide when to delegate.”
Required field, separate from the markdown body (the system prompt). Its own examples are third person, capability + trigger: “Expert code review specialist. Proactively reviews code for quality, security, and maintainability. Use immediately after writing or modifying code.”
OpenAI Agents SDKopenai.github.io/openai-agents-python
“handoff_description — a description of the agent, used when the agent is used inside tools/handoffs.”
Appended to the handoff tool description so the router knows when to pick it — while instructions is the system prompt that configures the agent’s own behavior. Same split, different names.
A2A 1.0 — the protocol we already implementa2a-protocol.org
“Client agents use the Agent Card to determine an agent’s suitability, structure requests, and ensure secure communication.”
The card’s description and skills[].description exist for another agent’s selection decision. The spec gives no composition guidance — so we take Claude Code’s, which is the most explicit of the three.
Anthropic — context engineering for agentsanthropic.com/engineering
“the minimal set of information that fully outlines your expected behavior” — and minimal “does not necessarily mean short.”
On the instructions side: aim for the right altitude — not brittle hardcoded logic, not vague platitudes; organize with markdown headings. This is what governs the long field, and why 2000 chars is a real cap rather than a placeholder.
Verdict: the split is not our invention — it is the convergent design. NeuraMesh is the outlier for having one field.

5 · What rex sees draft B4

list_agents selects name, role, model, status today — a roster with no capabilities in it, which is why the staffing ladder leans on role names alone. Adding description is the whole ask: rex can now tell a “developer who owns the sync layer” from a “developer who does UI”, and can justify a hire because nobody’s description covers the work.

list_agents · before → after
// today
{"in_channel":[{"name":"plume","role":"marketer","model":"opus-4-8","status":"online"}]}

// after
{"in_channel":[{"name":"plume","role":"marketer","status":"online",
  "description":"Drafts platform-native social copy and brand docs in the
   product's voice. Use for any post, campaign or messaging task; never for code."}],
 "workspace_not_in_this_channel":[{"name":"kestrel","role":"developer",
  "description":"Owns the PowerSync + sync-rules layer. Route schema,
   replication and offline-state work here."}]}
Budget: 280 chars × a 12-agent workspace ≈ 3.4 KB — about 900 tokens on a staffing turn. Real, bounded, and the reason the cap is 280 and not 2000.
The same string already has three other readers: the hover card, the roster page, and the A2A Agent Card. One field, four surfaces.

6 · The backfill draft B5

Every existing brief is already both fields glued together — a capability clause, then behaviour. The seeded ones make it obvious. So the migration splits at the first sentence, deterministically and reversibly, and both fields are editable from day one.

bosun · brief today — “Production-readiness plans and release coordination: study the approved change, surface every manual prod step with its owner, and merge only when the checklist clears.”
descriptionProduction-readiness plans and release coordination. Route release, deploy-step and merge-gate work here.
instructionsStudy the approved change, surface every manual prod step with its owner, and merge only when the checklist clears.
plume · brief today — “Brand and growth: study the product and its market for real, write the brand docs, draft platform-native content in the brand voice — and never publish anything; humans approve everything outbound.”
descriptionBrand and growth — brand docs and platform-native content. Route posts, campaigns and messaging here.
instructionsStudy the product and its market for real, write the brand docs, draft platform-native content in the brand voice — and never publish anything; humans approve everything outbound.
Seeded agents are code, not data — rex, iris, bosun, plume get hand-written descriptions in seed.ts, reviewed once, in the PR.
Hired agents get a deterministic split: description = first sentence, capped 280; instructions = the brief verbatim. Nothing is lost, nothing is invented.
Null is legal. An agent with no description lists as role alone — exactly today’s behaviour — so the backfill can never break staffing if a row is missed.
