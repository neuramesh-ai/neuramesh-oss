One loop, three ways to build it

NeuraMesh is a desktop-first, Slack-style workspace where a per-channel orchestrator agent fans tasks onto an enforced board, workers execute in git worktrees on users' own machines, validation artifacts are attached structurally, and review loops gate completion. Cloud holds true state; compute and code stay local. Agent-to-agent contract: A2A 1.0.

Where competitors sit full teardown in docs/01-product-review.md

Slock closest

Web-only, closed source. Has the board + machine-bound agents + multiplayer — but zero git story, no orchestrator (agents self-claim), no offline. We steal: daemon onboarding, enforced transitions, claim protocol, agent inbox, held-draft.

T3 Code engineering

MIT, 12.5k★. Worktrees, checkpoints, per-turn diffs, event-sourced core — but single-user, no team layer, and its CLI wrapping added ~3x latency. We steal the git mechanics; we beat it with cloud team state + thin runtime I/O.

OpenAgents protocol

Apache/MIT. Best-in-class protocol concepts (event envelope, addressing, presence) — but no board, no worktrees, web-first, bus factor ~1–2. Borrow concepts, don't build on it.

Option A — Managed Rails chosen ✓ 2026-06-10

Buy the undifferentiated infrastructure (sync, auth, storage); spend all six weeks on the loop. Electron + PowerSync + Supabase + Hono control plane + Claude Agent SDK.

Why it wins the 6-week race

  • Offline reads and writes out of the box (upload queue) — your hardest requirement, bought not built
  • Per-channel partial sync = a sync-rules config file, not code
  • Supabase gives Postgres + pgvector + auth + artifact storage in one console
  • All product effort goes to the loop: orchestrator, claims, worktrees, review

Eyes-open risks

  • beta PowerSync Node SDK in Electron main — verified in their own Electron guide, but week-1 spike is the go/no-go
  • Vendor pricing at scale ($49 → $599/mo tiers; self-host Open Edition exists — verify license)
  • Supabase Auth is basic — orgs/invites are our own tables (fine)
  • Exit path is real: → Option B swaps sync+auth only; schema, API, UI, agent layer unchanged

⏱ Time to full-loop alpha: ~6 weeks build this

Engineered so Option B is a swap (keep reads/writes behind a thin db facade) and Option C's event log exists from day one (append-only events table).

Option B — Own Rails the migration target

Same product, vendor-free data plane: ElectricSQL (Apache-2.0) read-path + TanStack DB optimistic writes through our own API + Better Auth + Neon/Fly Postgres. What Option A migrates toward when revenue justifies owning ops.

⏱ Time to full-loop alpha: ~8–9 weeks migrate here later

Pick B now only if the week-1 PowerSync spike fails, or if zero-lock-in is non-negotiable from day one. Otherwise it's the planned destination: A → B swaps the sync engine and auth; Postgres schema, control API, A2A gateway, agent layer, and UI carry over untouched.

Option C — Event-Sourced Maximalist not the 6-week pick

Own protocol end-to-end: commands → immutable event log → projections, per-channel event streams replicated to local SQLite over our own WS protocol. Optional Tauri v2 + Rust shell. The T3-Code-validated core, plus cloud multi-tenancy. The ceiling — and the longest road.

⏱ Time to full-loop alpha: ~12–16 weeks solo defer

Steal its soul today instead: A/B append every accepted command to an immutable events table (task timeline + audit log). When scale or enterprise demands it, that table grows up into this architecture without a rewrite of the product surface.

Operating modes how teams actually use it — all three options support all modes

Manual day 1 trust

Humans create and assign tasks; agents execute and validate; humans review. The board is still enforced. This is how teams build trust in week one.

Orchestrated the product

@mention the channel orchestrator: it decomposes, writes tasks, offers to skill-matched registered agents, dispatches reviews, posts digests. Humans approve merges.

Autonomous phase 2

Standing goals + scheduled routines; cloud-hosted orchestrator keeps loops running while laptops sleep; budgets + policy gates bound the blast radius.

Protocol — the enforced loop

Board states are the product surface; A2A 1.0 tasks are the wire. The server — never prompts — enforces transitions, atomic claims, and artifact-gated submission.

Task state machine server-enforced · adds blocked + accepted (human sign-off) to Slock's proven set

A2A 1.0 mapping verified against spec v1.0.0 · Linux Foundation

Design rule

A board task is the product entity; each execution attempt is an A2A task. Work attempt, review pass, and rework are separate A2A tasks sharing contextId = task:1042, linked via referenceTaskIds. Spec-exact (A2A has no "in_review" state) while the board tells the human story. Validation evidence = A2A Artifacts (Parts: url/data/text). Review loop declared as an A2A extension in Agent Cards. Review is dispatched automatically to the channel's reviewer pool (self-review blocked); after approval, done → accepted is a human sign-off recorded in the events log — channels may configure auto-accept for low-risk work. For repo-backed tasks, submit also requires the task branch pushed to the remote (review pinned to the submitted SHA) — acceptance becomes machine-independent, and phase-2 remote agents inherit the same contract with zero protocol change.

AX mechanics from Slock

  • Agent Inbox — pull, not push: agents query mentions/offers/reviews and choose what enters context
  • Held Draft — sends carry a room-version; if the channel moved, the send is held with a diff: revise / send / stay silent
  • @mention-gated wakes — no chatter storms

Memory spine own pgvector

  • Per-channel summary blocks — shared, editable, always in context (Letta pattern)
  • extract → reconcile fact writes: ADD/UPDATE/DELETE/NOOP (mem0 pattern)
  • Bitemporal validity — facts superseded, never overwritten (Graphiti)
  • HNSW + BM25 + RRF recall, channel-ACL-scoped (gbrain recipe) · <200ms budget

Security trust wedge

  • Daemons connect outbound-only — no open ports; code never transits unless attached
  • Machine-owner grants: repos × channels × permission mode per agent
  • BYOK — inference keys in the local keychain, never platform-held
  • Append-only events = audit log · recommend open-sourcing the daemon

Artifact library per channel

  • Validation evidence + shared files promoted from tasks into a channel library
  • Orchestrator curates: tags, versions, content-hash dedupe, pruning
  • ACL = channel registration · agents read via MCP artifacts.list / get / promote
  • A2A Artifact objects end-to-end · cross-channel sharing = explicit promotion (phase 2)

Threads channel hygiene

  • Thread-per-task: claims, requirement checks, progress, validation, review rounds live in the task's thread
  • Main channel gets orchestrator digests + clickable task summaries only
  • Keeps channels readable at fan-out scale; full detail one click away

Alpha success criteria

The loop, daily

A 3-person team + 5 agents runs orchestrator fan-out → claim → requirements → worktree → artifacts → auto-review bounce → done → accepted → PR, every day for a week.

Feels instant

Send → render <50ms · channel switch <100ms · cold start <2s · agent wall-clock overhead vs raw Claude Code <10% (T3's 3x is the anti-benchmark).

Survives a plane

Kill the app mid-task, reopen offline: full history readable, writes queue, agent sessions resume on reconnect.
