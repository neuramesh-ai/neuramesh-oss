2 · What progress looks like · 3 · How messages arrive

The proposed column above is also the answer to both: the grouped, expandable activity — the same rows the @rex · activity panel already renders — streams directly into the thread instead of hiding behind view full activity, and every line arrives with a short rise rather than popping in. Two genuine choices:

When a run finishes, the log…Recommended

Collapses to one summary line — “34 steps · 3 files · 2 commands” — still expandable. A finished thread stays readable; a month-old task doesn’t open as a wall of tool calls.

…or stays fully expanded

Everything remains on screen forever. Maximum transparency, but scrollback grows fast and the human-readable messages get buried between tool rows.

Message arrivalRecommended

Progressive reveal, ~260ms. Real token streaming where the daemon streams it; a short rise for messages that arrive already-complete over sync. Reads continuous, never fakes slowness.

…or true per-character typing

Characters typed out at a fixed rate. Looks alive, but it delays reading text that is already here — and a synced message from another machine would be pretending to be live.
