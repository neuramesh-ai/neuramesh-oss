Whiteboards — the thinking surface, and the first thing agents can draw

The ask (George, 2026-08-05): integrate Excalidraw. Humans quickly draft ideas or mockups and capture them into a chat as artifacts; agents generate whiteboard assets too (Excalidraw converts mermaid and element JSON into editable scenes); a left-nav item next to Board — or rename Board to Tasks — plus a New whiteboard entry in the workspace ＋ flyout; boards open in tabs, render as preview cards in threads, and can be edited or reviewed.

Verdict: yes — and the 08-03 hold is answered. The channel-scope round held Whiteboard (its Stop 6) because no job was named: "without an agent contract it's a drawing app inside a collaboration platform." This ask names the job twice over. Job 1 — think before there's a task: sketch in a chat-mode thread, the room's agents read it, and docs/34's escalation valve turns the conversation into work in place. Job 2 — agents finally draw: the repo has zero diagram surface today (not one mermaid reference anywhere) — plans, reviews and architecture discussions are prose-only. Both jobs run the litmus: sketches brief the design gate, architecture diagrams land in plan reviews, and visual evidence reaches review threads.

The guard from Stop 6 stands: a whiteboard is not a fourth home for design rounds. The Design Studio keeps `approve_design` and the visual contract; whiteboards are the pre-task sketch and the diagram — different noun, and the plan below enforces the boundary rather than promising it.

The engine is right. @excalidraw/excalidraw@0.18.1: MIT, React 19 peer (ours), a controlled component in the renderer; a scene is plain JSON, so a board syncs like any other row — PowerSync gives offline reads and queued writes for free. @excalidraw/mermaid-to-excalidraw@2.2.2 turns flowchart/sequence/class mermaid into editable elements (other types arrive as an image), and convertToExcalidrawElements() accepts a simple element skeleton — two generation paths that fit an LLM's hands. exportToSvg makes the snapshot every card renders. Assets self-host via window.EXCALIDRAW_ASSET_PATH: no CDN, no excalidraw.com call, ever — scene bytes live in our Postgres and nowhere else.

Stop 1Where it lives — a destination beside Tasks, scoped like everything else
The left column's destinations are one data-driven list (Home · Board · Automations · Library). Whiteboards slots in beside Board, and Board's label becomes Tasks — label only: the FSM, the docs and every internal id keep board. The scope knob at the column's head does to Whiteboards exactly what it does to Tasks and Automations: All channels = every board in the project, #room = that room's boards. The destination is a library of snapshot tiles — day-grouped like the session list, each tile a static SVG snapshot (never a live canvas), because a grid of running Excalidraw instances is how a 60fps budget dies.

6Sixth tab kind. wtabs.ts grows 'whiteboard': reuse keys on the board id (one board = one tab), the dirty dot replaces the ✕ mid-edit (the universal contract), and serialize/revive learn the kind so boards survive relaunch — identity in its own field, because tabs carrying artifactId are deliberately never persisted.
7Share to chat is the capture moment — it posts a snapshot card into a session you pick (defaults to the room the board is filed in). The board stays live; the card is the doorway back to it.
8The #room chip names the filing. A board created under a room scope files there; under All channels it takes your most recent room and the chip is where you move it. One decision, visible, undoable — the auto-file philosophy.
9Autosave, then reconcile. Debounced save (~1.5s idle) writes scene + a fresh SVG snapshot behind a revision guard. Clean tab + a remote edit = the canvas refreshes live (viewers watch a board change). Dirty tab + a remote edit = a conflict toast, take theirs or keep yours. Last-write-wins v1; live co-editing is named phase-2 work, not pretended.
10Theme, not tokens. Excalidraw gets theme: dark|light from the app theme and keeps its own island chrome — the xterm precedent. Its fonts ship in the app bundle (EXCALIDRAW_ASSET_PATH); collab, share links and cloud export are disabled via UIOptions.
11Job 1, worked example: a rough composer sketch made to brief the design gate — it becomes a designer's input, never the approved round itself.
Stop 3The thread card — humans capture, agents draw
One card, two directions. A human shares a sketch into a chat; an agent answers a request with a diagram it generated. Either way the transcript record is a snapshot card — the deliverable-card idiom with a canvas-ground image, kind-tagged, click-through to the tab. Agent generation goes through one new tool, create_whiteboard, registered everywhere a turn gets tools — the bus catalogue, the chat turn's registry and the worker's (they are deliberately separate; adding to one is not adding to the others): the agent submits mermaid or an element skeleton, both as strings — the lowest common schema every runtime speaks; the server validates, files the board, posts the card. The daemon never renders — mermaid needs a DOM, so the desktop materializes the scene on first render (idempotent, one winner), and every later mount reads the stored snapshot.

Stop 5The build — four slices, each shippable
Ordered so each slice is useful alone. New pure logic lands in a sibling module (whiteboards.ts beside wtabs.ts), tested from src/main/*.test.ts; App.tsx gains mounts, not logic. The table is a new synced table — the full checklist (migration · publication · sync rules · deploy notes), with the scene as jsonb per the ship_plan precedent.
Slice 1

The surface

whiteboards table (id · workspace · channel · title · scene jsonb · source · snapshot_svg · rev · by/at · archived) + whiteboard.create/update/archive commands (tenant-authz'd, rev-guarded, size-capped) + the one new piece of sync machinery: an uploadData branch (PUT/PATCH → rev-guarded LWW endpoint) — today only messages and attachments upload, so board edits are the first client-written synced rows beyond them. The 'whiteboard' tab kind, lazy-loaded Excalidraw, autosave + snapshot export, ＋ flyout entry.

Ships: a human draws, it syncs, it survives relaunch.
Slice 2

The destination

Whiteboards nav destination (the dest tuple + its three mirrors), snapshot-tile library grouped by day, scope-knob filtering, empty state, Board → Tasks label rename + tour copy. Open tile → tab.

Ships: George's nav ask, both labels settled.
Slice 3

Capture to chat

Share to chat posts a message whose marker the card renderer parses (the doc-drop pattern: a testable parser module, dispatched at both thread call sites); the body leads with a plain-text label line so mobile and old surfaces degrade readably. The card reads the board's synced snapshot — no duplicate bytes.

Ships: sketches reach threads; reviews gain diagrams.
Slice 4

The agent's hand

create_whiteboard in the chat + worker registries (mermaid | element skeleton), server validation + filing + card post, desktop materialize-on-first-render behind the scene IS NULL guard, prompt guidance ("flowchart/sequence/class arrive editable").

Ships: "sol, sketch the pipeline" works.
Invariants (enforced, not prompted): a whiteboard is filed to a channel; agent reads and writes are registration-checked server-side (human visibility is workspace-wide, the artifacts posture) · whiteboard.update carries a rev; a stale write returns WHITEBOARD_STALE and the client reconciles — no silent clobber · the new upload branch is explicit about PUT/PATCH and covered by tests — a local write that would be silently ACKed-and-dropped is the failure class it exists to prevent · scene ≤ 512KB, snapshot ≤ 150KB, embedded image files stripped at save v1 (WHITEBOARD_TOO_LARGE otherwise) · agents may update only boards they created; human boards are read-only to agents, server-side · a board in a chat-mode thread can never touch the task FSM (it is content, not state) · the Design Studio contract is untouched — approve_design never accepts a whiteboard, and the designer's rounds remain the visual contract · no network egress: Excalidraw assets ship in the bundle, and collab/share/cloud-export UI is compiled out via UIOptions.

Budgets (measured in the PR): Excalidraw is a lazy chunk — cold start unchanged (verify bundle) · first-ever board open ≤1.5s with a rising skeleton; every later open <100ms (the view-switch budget) · autosave off the interaction path; snapshot export <150ms on typical scenes · library tiles are static SVG — 60fps scroll · a shared card adds one <img> to a thread, no live canvas ever mounts in a list.

Deploy notes (the v0.5.0 lesson): new synced table ⇒ migration auto-applies, but the PR must call out the sync-rules deploy and the run's Deploy sync rules → success step (the check's ✓ lies when secrets are unset).

Phase 2, named so v1 stays small: live co-editing (self-hosted excalidraw-room or CRDT — LWW + live refresh covers the solo-and-turn-taking reality first) · versioned board rounds entering the review overlay with a verdict bar · images-in-scenes via the attachment path · mobile: snapshot in threads v1, read-only viewer later · board→backlog promotion ("circle it, park it") — the true "think with an agent" endgame · templates and a mermaid-paste door in the editor.

Open questions for this review: ① Board → Tasks — confirm the rename (my recommendation: yes; "Board · Whiteboards" adjacent is a collision) ② under All channels, New whiteboard files to your most recent room with the chip as the mover — acceptable, or should the flyout ask? ③ should agents be allowed to update their own boards in v1 (my draft says yes, creator-only), or create-only until the etiquette proves out? ④ does Share to chat also file an SVG into the channel artifact library, or is the Whiteboards destination the only shelf in v1 (my draft: destination only — one home per noun)?
