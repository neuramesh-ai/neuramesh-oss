Every door lands on the conversation — projects become the tree, needs-you becomes rows

The ask (George, 2026-08-07, from live v0.86 use): ① Share to chat from the Whiteboards destination re-opens the destination instead of a chat with the staged pill. ② Home / New chat clicked while a whiteboard tab is active appear to do nothing. ③ Recents should read like T3 Code's list — project, thread title, worktree + task id — and the consensus pattern: collapsible project groups in the left nav, each with a ＋ to start a chat in that project. ④ Retire the Home nav item (New chat IS the door, opening the chat home with the composer focused); attention counts move onto the thread rows themselves; the spine sheds its Home too. ⑤ Needs-you cards on the home shrink to clickable rows (the In-flight / Claude-desktop idiom) — answering happens in the thread.

Verdict on ①+②: one missing invariant, not two bugs. Nav doors (openWorkspaceHome, newChat, the destination tuples) mutate nav state but never activate tab 0 — so with a whiteboard tab active the surface changes invisibly underneath. Share does activate tab 0, but tab 0 renders whatever view is current — still whiteboards, a surface with no composer, so the staged pill has nowhere to appear. The fix is one function every door calls: land on the conversation tab, show a composer surface, focus it.

Round 2 (George, same day): ⑥ per-thread attention is color, not numerals — the row's own dial pulses in the accent (a chat row's hollow dot fills), and a collapsed group shows one accent dot; there is at most one ask per thread, so a count said nothing a color doesn't. ⑦ New chat inside a thread inherits its context — the chip arrives pre-set to that thread's project + channel, composer focused. ⑧ The `All channels` head is retired: channels become a per-project # filter on each group header (select which channels feed the group's rows, or create one in that project — the tune-menu shape). Destinations scope to the active project; the composer's own #channel chip is untouched.

Verdict on ③–⑤: yes — and it composes from idioms we already have. Task rows already carry their ⎇ branch second line (the recents-rows ruling); grouping nests them under project headers so the project reads as the group label, not a per-row prefix. The needs-you queue already derives from one source (needsyou.ts) — the same truth simply renders as row-pips in the tree and compact rows on the home, and the full decision card keeps living where it always did: in the thread, which is where answers belong.
