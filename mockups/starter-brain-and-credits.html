Starter brain, credits, and the setup tracker

round 2 · companion to docs/design/cloud-first-2026-08/starter-brain-and-credits.md · the flow for a user with NO subscription and NO API key: finish onboarding, get a real first reply, connect your own brain afterwards

The change in one line Keys stops being a wall

Today the browser wizard cannot be finished without a subscription or an API key — the Keys step gates Continue. This round makes it skippable: a user with neither still reaches a real first reply, on a platform-provided brain we meter with credits. Connecting their own brain doesn't disappear; it becomes the first item in a setup tracker they finish afterwards. The three screens below are the whole flow.

The skip is a door, not an escape hatch — two lines, styled as the one warm object on the step: an offer, not a consolation. No per-reply pricing (George, r2): a number nobody can act on at that moment is noise, and quoting a per-message rate makes a free product feel like a taxi meter. The reply says where it ran, not what it cost. Attribution ("on your cloud machine") is the promise being kept; a price tag on every message is a bill arriving in the middle of a conversation. The three named lines below stay — Brain, Machine and Storage are the three real costs and each is acted on differently (connect a brain, let the machine idle, prune a berth) — but they live in the usage view you click into, not in the thread. The always-visible surface is the rail, station 3. At the limit, replies queue with an honest line — never a hard wall mid-conversation.

3 · The credit tracker — in the rail, beside the person spending them always visible

The balance needs one ambient home, not a panel you remember to open. It joins the nav's bottom bar — workspace tile · name · account avatar as shipped — with the ring sitting left of the avatar: the balance belongs beside the person spending it, never drawn inside them. It depletes visibly, turns warm below a fifth, and opens the detail on click. No number in the resting state; a ring you can read at a glance is the whole point.

Why a ring and not a number. A number in the rail asks to be read; a ring asks only to be glanced at, and depletion is a shape before it is a figure. The three named lines survive — Brain, Machine, Storage, each acted on differently — but they live one click in, where someone who wants the breakdown goes looking. The popover's last line is the one that matters: connecting your own brain stops the drain entirely, which turns the meter into a reason rather than a threat. Placement note: the shipped bar is the workspace's, not the person's — adding a third element keeps its meaning honest only because the ring is the WORKSPACE's balance, which is exactly what credits are scoped to.

4 · The setup tracker — the fork worth deciding two placements drawn

Connecting a brain doesn't vanish when it's skipped; it becomes item one of a short list the user finishes at their own pace. The list is derived, never stored — from synced rows plus the usage read — so every client agrees without a checklist table to keep honest. The open question is where it lives. B — sits where the work is. Uses the existing card idiom, no new floating layer, and reads in the flow of the conversation the user just started. Cost: it scrolls away, so a user who ignores it once may never see it again — which is precisely the failure a tracker exists to prevent.
Recommendation: B now, A when it earns it. Ship the in-room card, which needs no new design-system idiom and lands with the round; add the floating pill only if telemetry shows people abandoning the list. The pill is easy to add later and hard to remove once people expect it — and a floating element that survives every screen is a claim on the whole shell, which docs/33 should approve deliberately rather than inherit from a checklist.

5 · Decisions this round needs

Mine to recommend — say no and I'll change them:
  1. Metered proxy, not a shipped key. The starter model is called from control-api, never from the machine. It's the only version where the cap is a server invariant instead of a client promise — and the current plan's "resolve through /v1/credentials/resolve" would put our key on every machine, unmetered.
  2. Credits, shown as credits with dollars beside them. 1 credit = $0.01. Internally micro-dollars so three meters share one integer unit.
  3. Three separate meters — Brain, Machine, Storage — never one blended score.
  4. Starter brain runs the orchestrator only, not the whole crew; worker agents wait for a real brain. A cheap model triaging is fine; a cheap model writing your code is a bad first impression.
  5. Tracker placement B (in-room card) this round; the floating pill only if it's earned.
Yours to settle:
  1. Grant size. Recommended: 500 credits ($5) at signup, refilling monthly, no rollover ≈ 250 replies. Model spend for a free user is well under $1/month — the machine is the expensive part (~$10–15), so the grant should be sized against machine cost, not model cost.
  2. Which Flash. gemini-1.5-flash is shut down, not deprecated. Recommended gemini-3.5-flash-lite at minimal thinking ($0.30/$2.50 per 1M) over 2.5-flash-lite ($0.10/$0.40) — 4× the cost per reply but far better tool-calling, and a model that mis-calls tools re-sends ~12k tokens per failed round.
  3. The Anthropic thread. Two questions now need written answers, and they take weeks: does the relay transporting an authorization code still satisfy the hosted-binary rail, and is the Agent SDK lane approved for us. Worth opening before GA, not at it.
  4. The Google OAuth exposure (unrelated to this round, found en route): the shipped desktop drives agy under a user's consumer Google login, which is the shape Antigravity's terms name as a breach and enforce with bans. Retiring that lane to API-key/Vertex matches what we already decided for cloud machines.
