Recents rows — branch, live state, and how much to say

The ask (2026-07-30): a task row should carry its worktree/branch on a second line, and a live view of what is happening in the thread — clean and more informative. Reference: the Codex sidebar's task rows (branch subtitle + expandable per-agent activity).

The constraint: the rail is 236px. Branches are long (nm/1009-copy-sweep-acme-marketing-…) — they truncate from the LEFT (tail-biased: the slug end is the identifying half). A freebie fix that ships with any variant: rail titles currently render raw markdown (⏱ **Routine — Thread-birth ch…) — titles get stripped to plain text.

The three variantsOne rail, three densities
All three share the anatomy: state dot (pulse = live run) · number · title · time, then a mono branch line with the ⎇ glyph on repo-backed tasks. They differ in how the LIVE state shows.

Why B: rest is exactly A (two lines max, live verb outranks branch for the second line — now-truth over stable-truth), and the expand answers "who did what, when" without leaving the rail — the reference's best idea, scoped to rows that have a journey. C is striking but degrades with concurrency.

Change surface (no new machinery): historyRows already carries the task — add `branch` passthrough · the live verb reads the same openRuns watch the pulse dot uses · expanded beats come from the synced beats/journey rows · title-markdown strip in threadTitle's rail render (the freebie) · CSS on the navhistrow anatomy · docs/33 idiom note.
