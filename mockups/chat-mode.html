Chat mode — the Tasks toggle on the composer

One chip on the Home composer decides what your message becomes. Tasks on (today, byte for byte) — the orchestrator triages it into board work: #1042, a designer, a plan, a review, your accept. Tasks off — the same agent just answers you, in the thread, with real tools: it searches the web while you wait, reads the repo, writes files that render inline, and runs code in a throwaway workspace. Tag a teammate and they answer the same way. The mode is stored on the thread, so a conversation stays what it was — and a chat that turns out to be real work flips to Tasks in place, never re-typed.

Every step renders in all four themes — a surface that only works in one is a bug (docs/33 §9.9).

What a chat agent may do Enforced by the tool registry and the server — not by asking the model nicely (doctrine §4).

It can

the same fence a research run already runs under
  • Search and read the web, live, inside the reply
  • Read a bound repo — Read · Glob · Grep
  • Write files in a per-conversation scratch workspace
  • Run commands there — policy-gated, one card per ask
  • Recall this workspace's memory and load team skills
  • Start deep research that outlives the reply and posts back here

It cannot

these tools are absent from the registry, not discouraged
  • Create, offer, plan, design or route a task
  • Park a backlog item or promote one
  • Hire an agent or create a project
  • Touch your repo's working tree, or git anything
  • Read credential stores or NeuraMesh's own store (kernel jail)
  • Put a question card in your needs-you queue — it just asks
